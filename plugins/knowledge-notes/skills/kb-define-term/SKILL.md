# 용어 정의 (kb-define-term)

용어 **하나**를 `term` 노트로 만든다. 여러 개면 `kb-atomize`를 쓴다.

## 0. 먼저 읽을 것

`${CLAUDE_PLUGIN_ROOT}/skills/kb-conventions/SKILL.md` — 특히 5장(용어 노트 표준 구조).

vault 경로는 `~/.knowledge-notes/config.json`에서 읽는다.

---

## 1. 중복 확인 (먼저)

노트를 만들기 전에 검색한다.

1. 파일명 검색
2. **`aliases` 검색** — 같은 용어가 다른 표기로 이미 있을 수 있다
3. 유사 표기 검색 — 띄어쓰기, 영문, 약어

있으면 **새로 만들지 않고 보강한다.** 이번에 쓴 표기를 `aliases`에 추가한다.

---

## 2. 정의 채우기

`${CLAUDE_PLUGIN_ROOT}/templates/term.md`를 사용한다.

```markdown
# 재고회전율

> 일정 기간 재고가 몇 번 팔려나갔는지 나타내는 비율.

## 산식
매출원가 ÷ 평균재고

## 사내 정의
- 우리 기준: (정의 · 산출 쿼리 위치 · 기준 수립 주체)
- 일반 정의와 다른 점:

## 혼동 주의
- [[재고일수]] — 역수 관계, 보고서에서 자주 뒤섞임

상위:: [[재고관리]]
```

### 한 줄 정의 (인용 블록)

- **한 문장.** 두 문장이 되면 뒤 문장은 설명이므로 `concept` 노트로 뺀다.
- 그 용어를 모르는 사람이 읽고 이해되는 수준으로 쓴다.

### 산식

수치 지표면 산식을 적는다. 산식이 없는 용어면 이 섹션을 지운다.

### 사내 정의 — **필수 섹션**

- 우리 회사에서 어떻게 쓰는지. 산출 위치(쿼리·테이블·문서)와 기준을 정한 주체.
- 일반 정의와 다른 점을 명시한다. 다르지 않으면 "일반 정의와 동일"이라고 쓴다.
- **모르면 `TODO: 사내 정의 미확인`으로 남긴다.** 일반 정의를 사내 정의 칸에 복사하지 않는다.
- 사내 문서에 정의가 있으면 **문서를 참조**한다. 내용을 통째로 복사하지 않는다.
  원본이 바뀌면 복사본은 거짓이 된다.

### 혼동 주의

비슷해서 뒤섞이는 용어를 `대조::`로 건다. 왜 헷갈리는지 한 줄로 쓴다.
(역수 관계, 분모가 다름, 영문이 같음 등)

---

## 3. frontmatter

```yaml
---
type: term
aliases: [재고 회전율, inventory turnover, ITR]
domain: [재고]
status: seed
created: 2026-09-14
schema: 1
---
```

**`aliases`를 반드시 채운다.** 떠오르는 표기를 모두 넣는다. 이게 다음번 중복을 막는다.

---

## 4. 저장과 연결

- `100_terms/` (설정의 `folders.term`)에 저장
- `상위::`로 더 큰 개념에 붙인다. 없으면 만들지 말고 비워둔다
- 출처가 있으면 `근거::`로 `source` 노트에 건다

---

## 5. 마무리

```
[[재고회전율]] 생성 (term, seed)
alias: 재고 회전율, inventory turnover, ITR
빈 링크: [[재고관리]], [[평균재고]], [[재고일수]]
확인 필요: 사내 정의 미확인 — 산출 쿼리 위치와 기준 수립 주체
```

빈 링크는 다음에 정리할 후보다. 자동으로 만들지 않는다.
