# vault 점검 (kb-audit)

노트는 쌓이는 순간부터 어긋나기 시작한다. 주기적으로 점검한다.

## 0. 먼저 읽을 것

`${CLAUDE_PLUGIN_ROOT}/skills/kb-conventions/SKILL.md` — 판정 기준의 원본.

vault 경로는 `~/.knowledge-notes/config.json`에서 읽는다.

---

## 1. 점검 항목

### 1-1. 중복·유사 노트

- 파일명 유사도 (띄어쓰기, 영문/국문, 약어)
- `aliases` 충돌 — **두 노트가 같은 alias를 갖고 있으면 거의 확실히 중복이다**
- 한 줄 정의가 거의 같은 `term` 노트

→ 자동으로 합치지 않는다. 후보를 보여주고 사용자가 판단하게 한다.

### 1-2. 빈 링크

`[[ ]]`로 걸려 있지만 파일이 없는 것. **참조 횟수 순으로 정렬한다.**
참조가 많은 빈 링크가 다음에 만들 노트다. 이건 고칠 대상이 아니라 **할 일 목록**이다.

### 1-3. 고아 노트

들어오는 링크도 나가는 링크도 없는 노트. 만들어놓고 연결을 안 한 것이다.
어디에 붙을지 제안한다.

### 1-4. frontmatter 누락·오류

- `type`이 5종에 없음
- `schema` 없음 — **마이그레이션 대상을 찾을 수 없게 된다. 최우선 수정**
- `created` 없음 / 형식 오류
- `aliases`가 비어 있는 `term` 노트 — 중복이 생길 자리다
- `status`가 seed → growing → stable 밖의 값

### 1-5. 원자성 위반

- 제목에 "그리고", "및", "와/과"가 들어간 노트
- `concept`·`insight`인데 제목이 명사구
- 한 노트에 `##` 섹션이 8개 이상 — 쪼갤 후보
- `term` 노트인데 판단이 섞여 있음 ("우리는 이걸 잘못 쓰고 있다" → `insight`로 분리)

### 1-6. 미해결 TODO

`TODO: 사내 정의 미확인` 같은 표시를 모은다. 오래된 것부터 정렬한다.

### 1-7. 관계 어휘 위반

6개(`상위`,`구성`,`선행`,`대조`,`근거`,`적용`) 밖의 인라인 필드가 쓰였는지.

## 2. 리포트 형식

```
vault 점검 — 노트 142개 (term 68, concept 31, insight 28, source 12, moc 3)

■ 즉시 고칠 것
  schema 누락            4개   → 목록
  type 오기입            1개   [[품절 대응]] type: insigt

■ 판단 필요
  중복 의심              3쌍
    [[재고회전율]] ↔ [[재고 회전율]]   alias 충돌
    [[반품률]] ↔ [[return rate]]      정의 거의 동일
  원자성 위반            5개
    [[안전재고와 리드타임]]  → 2개로 분리 제안

■ 할 일 목록 (빈 링크, 참조 많은 순)
  [[안전재고]]     7회
  [[리드타임]]     5회
  [[BNK]]         3회

■ 미해결 TODO        9건 (최장 84일 경과)
  [[반품률]]  사내 정의 미확인 (2026-06-22)

■ 고아 노트          6개
```

---

## 3. 수정

- **즉시 고칠 것**(frontmatter 오류)은 사용자 승인 후 일괄 수정한다.
- **판단 필요**는 자동으로 건드리지 않는다. 하나씩 물어본다.
- **빈 링크는 고치는 게 아니다.** 목록으로 남긴다.
- 노트를 삭제하지 않는다. 합칠 때도 내용을 버리지 않는다.
