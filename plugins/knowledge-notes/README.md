# knowledge-notes

새로 알게 된 지식(용어·개념·판단)을 **atomic 노트**로 분해해 Obsidian vault에 쌓고
링크로 연결한다.

배포 모델은 **각자 개인 vault + 규칙만 통일**이다. 공용 vault는 만들지 않는다.
규칙이 같으면 나중에 합칠 수 있고, 규칙이 다르면 합칠 수 없다.

## 시작하기

```
/kb-setup
```

vault 경로를 묻고 `~/.knowledge-notes/config.json`을 만든다. 폴더가 없으면 만들고,
시드 노트(48개)를 설치할지 묻는다.

## 쓰는 법

| 커맨드 | 언제 |
|---|---|
| `/kb-add` | 지금 내용을 바로 노트로 만들 때 |
| `/kb-review` | **주 1회.** 한 주치에서 지식화할 것을 골라낼 때 |
| `/kb-audit` | 중복·빈 링크·고아 노트 점검 |
| `/kb-setup` | 최초 설정, 설정 변경 |

말로 불러도 된다 — "이 문서 정리해줘", "이 용어 뭐야", "노트로 만들어줘".

**주력은 `/kb-review`다.** 매 턴 "지식화할까요?"를 띄우지 않는 이유는 사흘 안에 전원이
무시하게 되기 때문이다. 한 주를 모아서 보면 **반복 등장한 것**이 보이고, 그게 진짜
지식화할 가치가 있는 것이다.

## 스킬

| 스킬 | 하는 일 |
|---|---|
| `kb-conventions` | 규칙 원본. 다른 스킬이 참조한다 (사용자 호출 안 함) |
| `kb-atomize` | 원문 → 원자 노트 분해 |
| `kb-define-term` | 용어 하나 정의 |
| `kb-audit` | 중복·빈 링크·고아·규칙 위반 점검 |

## 고정 규칙 (설정으로 뺄 수 없음)

이게 통일되지 않으면 나중에 노트를 합칠 수 없다.

1. **노트 타입 5종** — `term` / `concept` / `insight` / `source` / `moc`
2. **frontmatter 스키마** — `type`, `aliases`, `domain`, `status`, `created`, `schema`
3. **관계 어휘 6개** — `상위` `구성` `선행` `대조` `근거` `적용`. 추가·변경 금지
4. **원자성 판정** — 제목에 "그리고"가 들어가면 쪼갠다

자세한 내용은 `skills/kb-conventions/SKILL.md`.

## 설정으로 빼는 것

`~/.knowledge-notes/config.json`

- vault 경로
- 폴더 번호 체계 (기본값 제공)
- 개인 태그
- 언어 표기 선호

폴더는 **타입으로만** 나눈다. 주제별 폴더(영업/데이터/S&OP)를 만들면 한 노트가 두 곳에
속하는 문제가 반드시 생긴다. 주제는 링크와 `domain` 필드로 처리한다.

```
000_inbox/        원문 투입, 미분해
100_terms/
200_concepts/
300_insights/
400_sources/
900_maps/
```

## 이 플러그인의 존재 이유

`kb-atomize`의 **3단계 — 기존 vault 검색 + alias 대조**다.
이게 없으면 템플릿과 다를 바 없고, 유사 노트가 계속 생긴다.

`aliases`가 실질적으로 가장 중요한 필드인 이유도 같다. 국·영문·약어를 섞어 쓰는 환경에서
alias가 없으면 "재고회전율", "재고 회전율", "inventory turnover", "ITR"이 전부 별개 노트가 된다.

**빈 링크 리포트는 버그가 아니라 자산이다.** 아직 노트가 없는 링크가 곧 다음에 정리할
우선순위 목록이 된다.

## 시드 노트

`seeds/`에 48개가 들어 있다. 빈 플러그인은 아무도 쓰지 않는다.

| 폴더 | 수 | 내용 |
|---|---|---|
| `100_terms` | 39 | 출고·재고·채널·도서·데이터 용어 |
| `200_concepts` | 6 | 집계·합산에서 반복되는 함정 |
| `300_insights` | 3 | 확인된 사내 판단 |
| `900_maps` | 3 | 출고와 판매 / 재고관리 / 데이터 인프라 MOC |

**대부분의 `사내 정의` 섹션은 `TODO`로 비어 있다.** 일반 정의는 채워져 있고, 사내 기준은
확인되지 않았기 때문에 비워둔 것이다. 추정으로 채우지 않았다. 확인되는 대로 채우면 된다.

## 미결 사항

- 훅 도입 여부 — 1차는 커맨드만으로 간다. 정착 후 판단한다
  (도입한다면 `type: "prompt"` 훅으로 먼저 판정시키고 조건 충족 시에만 제안, 세션당 1회 제한)
- 시드 용어 추가 — 영업 실무·마케팅 영역이 비어 있다
