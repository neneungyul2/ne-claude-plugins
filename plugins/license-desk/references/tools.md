# license-desk 도구와 폴백

원칙: **외부 시스템 접근은 흐름(스킬)이 하고, 역할(에이전트)은 건 폴더에 모인 파일만 다룬다.**
MCP 도구 이름은 실행 환경(Claude Code, Cowork)마다 달라서 에이전트에 박지 않는다.

## 건 폴더

- 위치: `<저작권 폴더>\계약서\<연도 폴더>\<업체>\_license-desk\<YYMMDD>_<건유형>\`
- 흐름이 원자료를 여기에 모으고, 각 역할은 결과를 여기에 쓴다
- 최종 초안(회신 메일, 계약 문서)도 여기에 둔다. 확정본을 업체 폴더로 옮기는 일은 사람이 한다

## 진행 장부

- 위치: `<저작권 폴더>\license-desk_진행장부.xlsx` (license-tracker만 씀)
- `1. CP 계약 관리.xlsx`는 읽기만 한다. 장부와 다른 값이 있으면 차이를 보고한다

## 시스템별 접근 순서

| 자료 | ① 자동 | ② 대체 | ③ 사람에게 요청 |
|---|---|---|---|
| 업체 메일 | Outlook 메일 검색·읽기 (M365) | 사용자가 메일 본문 붙여넣기 | `[메일 원문 없음]` |
| 계약서·계약현황·운영 원칙 | 내 PC 저작권 폴더 직접 읽기 | M365 SharePoint 검색 (OneDrive 업무자료). 결과에 "검색 일부만 됨" 표시 | 파일 업로드 요청, 칸은 `[못 찾음]` |
| 법무 검토·품의 상태 | ne-edoc 전자결재 조회 (`계약서 검토 요청서`, `품의서` 양식) | 사용자에게 결재 상태 확인 | 장부에 `[상태 미확인]` |
| 매출 증빙 | 업체 메일 첨부 | 저작권 폴더 내 증빙 파일 | 할인율 `[잠정]` |

- 도구 호출이 실패하거나 도구가 없으면 다음 칸으로 넘어간다
- 어느 칸을 썼는지 건 폴더의 `sources.md`에 적는다

## 전자결재로 단계 판별

| 결재 문서 | 판별 단계 |
|---|---|
| `계약서 검토 요청서` 결재완료 | 7. 법무 검토 완료 |
| `품의서` 결재완료 | 10. 자사 품의 완료 (상대 품의는 메일로 확인) |
| 대리중개수수료 `비용결의서` | 12 이후 정산 |

## 계산

`${CLAUDE_PLUGIN_ROOT}/scripts/calc_fee.py <입력.json>` — 판단 없이 계산만 한다. license-fee-calc가 입력 JSON을 만들고 실행한다. 흐름은 검수 전에 같은 입력으로 다시 실행해 초안 숫자와 맞춰 본다.
