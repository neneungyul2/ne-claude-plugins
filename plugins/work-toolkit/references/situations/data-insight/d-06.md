# d-06. 성과 리포트는 쓰는데 다음 기획은 또 감으로 정할 때

## 이럴 때
결과 정리로 끝나고, 잘된 안을 그대로 반복한다. 배운 게 쌓이지 않는다.
성과를 **다음 기획의 실험 가설**로 연결한다.

## 먼저 확인할 것
- 최근 성과 리포트·원본 데이터
- 상위·하위 성과 사례
- 지난 기획의 가설
- 이번 기획의 목표·제약
- 유지·제외할 기준

## 진행
성과가 좋았다는 이유만으로 모든 요소를 그대로 반복하지 말고,
**데이터에서 확인된 배운 점과 아직 검증되지 않은 해석을 구분**한다.
한 테스트에서 여러 요소를 동시에 바꾸지 말고, 각 안이 하나의 가설만 검증하도록 설계한다.
판단 기준을 계산하는 데 필요한 데이터가 부족하면 임의의 수치를 제안하지 말고 필요한 데이터를 먼저 알린다.

## 출력
1. **지난 성과 요약** — 목표 대비 결과와 상위·하위 성과를 핵심 수치 중심으로.
2. **배운 점** — 유지할 요소, 중단할 요소, 아직 판단할 수 없는 요소를 근거와 함께.
3. **다음 검증 가설** — 우선순위가 높은 가설 3개를 '만약 ~하면, ~지표가 ~할 것이다' 형식으로.
4. **기획안 후보** — 가설마다 하나의 변수만 바꾼 실행안과 나머지 통제 조건.
5. **측정 계획** — 주요 지표, 보조 지표, 비교군, 측정 기간, 성공·중단 판단에 필요한 데이터.
6. **실행 우선순위** — 기대효과, 실행 난이도, 학습 가치 기준의 순서.
7. **다음 리포트에 남길 항목** — 실험 후 기록해야 할 결과와 배운 점을 체크리스트로.

## 주의
- "잘됐으니 그대로 간다"는 학습이 아니다. 무엇 때문에 잘됐는지 가설을 남긴다.
- 중단 기준을 먼저 정한다. 그게 없으면 실패한 안을 계속 붙잡는다.
