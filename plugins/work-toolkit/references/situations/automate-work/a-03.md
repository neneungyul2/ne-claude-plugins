# a-03. AI에게 매번 같은 배경과 기준을 처음부터 설명하고 있을 때

## 이럴 때
대화마다 업무 맥락을 다시 설명하고, 결과물이 매번 달라진다.
맥락과 기준을 **재사용 가능한 문서**로 고정한다.

## 먼저 확인할 것
- 반복해서 설명하는 업무 배경
- 반드시 지킬 규칙과 금지 사항
- 좋은 결과물과 나쁜 결과물의 예시
- 맡길 업무 범위
- 기록·업데이트할 항목

## 진행
매번 긴 설명을 다시 쓰지 않도록 정보를 **성격별로 나눠 재사용 가능한 문서**로 설계한다.
변하지 않는 규칙과 작업할 때마다 달라지는 상태를 구분한다.
**모르는 내용을 추정하지 않도록 확인·보고 규칙도 포함한다.**

## 출력
1. **업무 맥락 문서** — 업무 목적, 항상 지킬 규칙, 금지 사항, 기본 작업 순서.
2. **작업 절차 문서** — 반복 업무의 입력값, 단계별 실행법, 출력 형식, 완료 기준.
3. **진행 상태 문서** — 현재 진행 상태, 완료한 일, 다음 할 일, 막힌 지점을 기록할 템플릿.
4. **누적 기록 문서** — 다음 작업에도 유지할 결정, 선호, 수정 이력을 기록할 항목.
5. **업데이트 규칙** — 어떤 정보가 바뀌었을 때 어느 문서를 수정해야 하는지 표로.
6. **자기 점검** — 작업 전후로 스스로 확인할 체크리스트.
7. **첫 검증 과제** — 규칙을 제대로 이해했는지 검증할 작은 테스트 업무와 합격 기준.

## 주의
- 이 결과물이 반복해서 쓰인다면 **스킬이나 플러그인으로 만드는 것**이 다음 단계다.
  사내 배포까지 필요하면 `ne-claude-plugins` 마켓플레이스에 추가하는 방법을 안내한다.
- 문서가 네 개로 늘어나면 관리가 부담이다. 처음에는 업무 맥락 문서 하나로 시작해도 된다.
