# a-05. 정해진 시간에 업무가 자동으로 처리되게 하고 싶을 때

## 이럴 때
매번 내가 지시해야 시작되고, 출근 후에 결과물을 정리한다.
정해진 시간에 **먼저 실행되고 결과가 저장**되게 만든다.

## 먼저 확인할 것
- 반복 실행할 업무
- 실행 요일·시간
- 참고할 데이터·문서
- 결과를 저장할 위치
- 실패·승인 알림 기준

## 진행
정해진 시간이 되면 필요한 자료를 읽고 업무를 수행한 뒤 결과를 기록하는 흐름을 설계한다.
**실행 전 필수 입력값과 접근 권한을 확인**하고, 데이터가 없거나 연결이 실패하면
임의로 진행하지 말고 상태와 필요한 조치를 남긴다.
**외부 발송·게시·삭제처럼 되돌리기 어려운 행동은 사람의 승인 뒤에만 실행한다.**

## 출력
1. **자동 실행 목표** — 반복 업무의 시작 조건, 완료 결과, 자동화할 이유를 한 문장씩.
2. **실행 트리거** — 실행 요일·시간·시간대와 중복 실행을 막을 조건.
3. **작업 흐름** — 자료 확인 → 업무 실행 → 자기 검수 → 저장 → 완료 보고 순서.
4. **저장 구조** — 결과를 남길 위치와 필요한 속성, 상태값, 입력·결과 필드, 업데이트 규칙.
5. **권한과 승인** — 자동 실행할 일, 사람의 승인을 받은 뒤 실행할 일, 실행하지 말아야 할 일.
6. **오류·예외 처리** — 데이터 누락, 권한 오류, 연결 실패, 중복 실행 시의 대응과 알림 방식.
7. **테스트와 운영** — 처음에는 수동으로 시험할 테스트 케이스, 성공 기준, 정기 실행 전 점검 항목.

## 주의
- 사내 배포용 정기 실행이라면 세션 내부 스케줄러가 아니라 **계정 단위 스케줄 기능**을 쓴다.
  세션이 끝나면 사라지는 방식은 조용히 실행되지 않는다.
- 알림 없는 자동화는 실패해도 아무도 모른다. 실패 알림 경로를 반드시 만든다.
