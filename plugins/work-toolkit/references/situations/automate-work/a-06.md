# a-06. 같은 업무가 매번 다르게 처리되어 표준 절차(SOP)로 만들어야 할 때

## 이럴 때
같은 업무인데 매번 다르게 처리되고, 매번 설명을 다시 한다.
머릿속 절차를 **문서로 표준화**한다. 자동화보다 이게 먼저다.

## 먼저 확인할 것
- 업무 정의 (한 줄)
- 목적과 주요 사용자 (누가 이 문서를 쓰는지)
- 현재 업무 흐름과 문제점
- 앞으로 적용할 표준 흐름
- 입력물과 출력물 (형식 포함)
- 반드시 지켜야 할 규칙·정책
- 자주 발생하는 예외·오류와 대응
- 완료 기준·검수 방법
- 관리 담당자와 업데이트 주기

## 출력 (아래 셋 중 하나)

### A. SOP 초안
1. **단계별 절차** — 번호 + 각 단계의 목적과 주의점.
2. **입력·출력물 표** — 링크·파일명 규칙 포함.
3. **완료 전 체크리스트** — 10~15개.
4. **자주 묻는 질문** — 5개.

### B. 표준화 템플릿·체크리스트
1. **실행 체크리스트** — 착수·진행·완료 3단.
2. **입력물 확인 리스트** — 권한·자료·버전.
3. **산출물 템플릿** — 헤더·목차·필수 항목.
4. **검수 체크리스트** — 품질·정확·형식 10개.

### C. 배포 공지 + 운영 규칙
1. **팀 공지** — 왜 → 무엇이 → 어떻게 쓰나 → 링크.
2. **온보딩 5줄 요약** — 신규 입사자용.
3. **문서 운영 룰** — 5개. 업데이트·피드백·버전 관리.
4. **정착 확인** — 2주 후 점검 질문 3개.

## 주의
- 실제로 하는 방식과 문서가 다르면 문서가 죽는다. 이상적인 절차가 아니라 지금 하는 절차부터 쓴다.
- 예외 처리가 없는 SOP는 첫 예외에서 버려진다.
- SOP가 정착된 뒤 a-01(자동화 우선순위)로 넘어간다.
