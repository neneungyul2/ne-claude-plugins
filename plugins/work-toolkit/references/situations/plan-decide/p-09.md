# p-09. 일정이 밀리고 있어 작업을 다시 쪼개고 계획을 새로 짜야 할 때

## 이럴 때
승인 대기·검수가 겹치면서 계속 밀린다. 오늘 안에 다시 쪼개고 우선순위와 버퍼를 조율해야 한다.

## 먼저 확인할 것
- 산출물 정의 — 최종적으로 낼 결과물
- 고정 마감 vs 조정 가능한 중간 마일스톤
- 현재 진행 상태 — 완료 / 진행 중 / 남은 일
- 작업 목록 — 태스크 단위로 누락 없이
- 태스크별 예상 소요와 난이도
- 의존성·선행 조건 (승인·자료·타 팀 협조)
- 실제 가용 시간 (회의·기타 업무 제외)
- 필수 검수·품질 기준
- 일정을 흔들 수 있는 리스크

## 출력 (아래 셋 중 하나)

### A. 태스크 분해 → 우선순위 → 현실 일정
1. **태스크 분류** — 필수 / 선택 / 후순위 + 우선순위 상위 10개.
2. **일정표** — 일자·시간 블록 또는 주간 플랜(마일스톤 포함).
3. **크리티컬 패스** — 지연되면 전체가 밀리는 태스크 표시.
4. **매일 체크인 템플릿** — 진척·블로커·다음.

### B. 플랜 A + 플랜 B
1. **플랜 A 일정** — 마일스톤·담당·산출물 기준.
2. **리스크 상위 5개** — 확률·영향·트리거·완화 방안.
3. **플랜 B** — 범위 축소·단계 제공·검수 간소화 등과 발동 조건.
4. **즉시 요청할 지원·결정** 목록.

### C. 상태 업데이트 + 조정 제안 메시지
1. **상태 요약** — 현재·리스크·다음 단계, 3줄.
2. **조정 제안 옵션** — 2~3개 (기한 조정·범위 축소·단계 제공).
3. **추천안** — 1개와 이유.
4. **선택형 결정 질문** — 1~2개.
5. **메신저 버전 / 메일 버전** — 메일에는 제목 포함.

## 주의
- 가용 시간을 하루 8시간으로 잡지 않는다. 회의와 다른 업무를 뺀 실제 시간으로 계산한다.
- 버퍼 없는 계획은 이미 밀린 계획이다. 최소 20%는 남긴다.
