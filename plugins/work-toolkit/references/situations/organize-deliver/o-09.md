# o-09. 상사·타 부서에 진행 상황이나 지원 필요 사항을 보고해야 할 때

## 이럴 때
급해서 상황만 먼저 말했는데, 뭐가 막혔고 언제까지 어떤 지원이 필요한지 정리가 안 돼 판단을 못 받는다.

## 먼저 확인할 것
- 업데이트 목적 (상태 공유 / 리스크 공유 / 지원 요청)
- 수신자와 그들이 중요하게 보는 포인트
- 과제 정의 (한 줄)
- 현재 상태 (정상/주의/위험 + 진척률)
- 완료된 성과
- 진행 중 작업과 다음 계획
- 리스크와 필요한 지원 (숨기지 않는다)
- 다가오는 일정·마일스톤
- 확정/미확정 구분

## 출력 (아래 셋 중 하나)

### A. 진행 상황 공유 메시지
1. **메신저 버전** — 5줄. 상태 → 성과 → 다음 → 리스크 → 요청.
2. **메일 버전** — 제목 포함, 8~12줄.
3. **선택형 질문** — 상대가 바로 답할 수 있는 것 1~2개.
4. **다음 업데이트 시점** 한 문장.

### B. 이슈 설명 + 지원 요청
1. **사실 요약** — 무슨 일이 / 언제부터 / 현재 상태, 3줄.
2. **영향** — 일정·품질·범위, 3줄.
3. **대응** — 현재 조치 / 플랜 A·B, 5줄.
4. **요청** — 결정·자원·우선순위 1~2개(선택형 질문 포함).
5. **다음 체크인 시점**.

### C. 수신자별 버전
1. **상사 버전** — 결론·리스크·요청 중심.
2. **타 부서 버전** — 의존성·핸드오프·요청 중심.
3. **공통 한 줄 요약** — 제목·첫 줄용.

## 주의
- 상태가 '주의'나 '위험'이면 그렇게 쓴다. 좋게 포장하면 지원을 못 받는다.
- 요청이 없는 진행 보고는 읽히지 않는다. 최소한 "확인만 부탁드립니다"라도 명시한다.
