# o-07. 피드백을 받았는데 무엇부터 고쳐야 할지 모를 때

## 이럴 때
"메시지가 약하다", "의사결정에 쓰기엔 애매하다" 같은 모호한 피드백이 왔다.
보이는 문장부터 고치면 방향이 흔들린다. **목적에 영향이 큰 것부터** 반영한다.

## 먼저 확인할 것
- 현재 초안
- 받은 피드백 원문
- 문서의 목적과 독자
- 마감과 유지할 조건 (예: 오늘 제출·핵심 주장 유지)

## 진행
피드백을 무조건 모두 반영하지 말고, **문서 목적과 독자 이해에 미치는 영향**을 기준으로 판단한다.
의미가 모호하거나 서로 충돌하는 피드백은 임의로 해석하지 말고 확인 질문으로 바꾼다.

## 출력
1. **피드백 요약** — 구조·논리·근거·표현·형식으로 묶어 핵심 요구를 정리.
2. **반영 판단** — 각 피드백을 '즉시 수정' / '확인 후 수정' / '보류·제안' 으로 나누고 판단 이유.
3. **우선순위** — 목적 영향도, 수정 긴급도, 수정 범위를 기준으로 1~3순위.
4. **충돌과 누락** — 서로 충돌하는 피드백, 원문만으로 판단하기 어려운 내용, 추가로 필요한 자료.
5. **수정 계획** — 수정할 위치, 바꿀 내용, 유지할 내용, 예상되는 연쇄 수정 범위를 표로.
6. **확인 질문** — 피드백을 준 사람에게 짧고 구체적으로 물어볼 질문.
7. **수정** — 우선순위 1순위에 해당하는 부분부터 원래 의도를 유지해 수정. 바뀐 내용과 수정 이유를 함께 표시.

## 주의
- '보류·제안'이 있어야 정상이다. 전부 '즉시 수정'이면 판단을 안 한 것이다.
- 재검토를 요청할 때는 "무엇을 봐달라"는 확인 포인트 3개를 함께 보낸다.
