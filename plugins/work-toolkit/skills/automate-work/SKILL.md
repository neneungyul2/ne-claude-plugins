# 반복 업무를 넘길 때

## 0. 먼저 읽을 것

${CLAUDE_PLUGIN_ROOT}/references/output-rules.md — 공통 출력 규칙. 건너뛰지 않는다.

## 1. 상황 판별

| id | 이럴 때 |
|---|---|
| a-01 | 반복 업무는 많은데 무엇부터 자동화해야 할지 모르겠다 |
| a-02 | 매주 같은 데이터를 복사해 보고서를 다시 만들고 있다 |
| a-03 | AI에게 매번 같은 배경과 기준을 처음부터 설명하고 있다 |
| a-04 | 콘텐츠를 만들 때마다 같은 제작 과정을 반복하고 있다 |
| a-05 | 정해진 시간에 업무가 자동으로 처리되게 하고 싶다 |
| a-06 | 같은 업무가 매번 다르게 처리되어 표준 절차(SOP)로 만들어야 한다 |

a-06(SOP)이 먼저다. 절차가 글로 정리되지 않은 일은 자동화할 수 없다.

## 2. 절차

1. 위 표에서 맞는 id를 고른다.
2. `${CLAUDE_PLUGIN_ROOT}/references/situations/automate-work/<id>.md` 를 Read 도구로 읽는다.
3. 그 문서의 지침을 그대로 따른다.
4. **표에 없으면** 아래 3장의 공통 원칙으로 처리한다.

## 3. 이 영역의 공통 원칙

- **업무를 통째로 자동화하지 않는다.** 조건-행동-결과로 쪼개고, 가장 작고 안전한 단계부터 시작한다.
- **판단과 승인이 필요한 단계는 사람에게 남긴다.** 외부 발송·게시·삭제처럼 되돌리기 어려운 행동은 승인 뒤에만 실행한다.
- **데이터가 없거나 형식이 다르면 멈춘다.** 임의로 채우고 진행하지 않는다. 멈춘 이유를 알리는 경로를 반드시 설계한다.
- 자동화 전후로 **사람이 확인할 항목**을 체크리스트로 남긴다.
- 실패·예외 처리를 먼저 정의한다. 잘 될 때만 생각한 자동화는 반드시 사고를 낸다.
- 처음에는 수동으로 몇 번 돌려 검증한 뒤 자동 실행으로 넘긴다.
