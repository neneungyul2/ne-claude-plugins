# CASE 3. 일정 압박 → 재계획

## 상황
승인 대기·검수 단계가 겹치는 등으로 일정이 계속 밀리는 상황. 오늘 안에 작업을 다시 쪼개고 우선순위/버퍼를 조율해야 한다.

## 먼저 확인할 정보
1. 산출물 정의 — 최종적으로 낼 결과물
2. 마감(고정) vs 조정 가능한 중간 마일스톤
3. 현재 진행 상태 — 완료/진행 중/남은 일
4. 작업 목록 — 누락 없이 태스크 단위
5. 태스크별 예상 소요·난이도
6. 의존성·선행 조건(승인/자료/타 팀 협조)
7. 실제 가용 시간(미팅/온콜/핵심 업무 제외)
8. 필수 검수·품질 기준
9. 일정을 흔들 수 있는 리스크 요인
10. 중간점검 주기와 출력 형태(일정표/주간 플랜)

## 만들 수 있는 산출물

### A. 태스크 분해 → 우선순위 → 현실 일정
- 태스크를 '필수/선택/후순위'로 분류 + 우선순위 TOP 10
- 일정표(일자/시간 블록) 또는 주간 플랜(마일스톤 포함)
- 크리티컬 패스(지연 시 전체가 밀리는 태스크) 표시
- 매일 체크인 문장 템플릿 1개(진척/블로커/다음)

### B. 플랜 A(기본) + 플랜 B(리스크 발생 시)
- 플랜 A 일정(마일스톤/담당/산출물 기준)
- 리스크 TOP 5(확률/영향/트리거/완화 방안)
- 플랜 B 제안(범위 축소/단계 제공/검수 간소화 등) + 발동 조건
- 지금 즉시 요청해야 할 지원/결정 리스트

### C. 상태 업데이트 + 조정 제안 메시지
- 상태 요약 3줄(현재/리스크/다음 단계)
- 조정 제안 옵션 2~3개(기한 조정/범위 축소/단계 제공)
- 추천안 1개 + 이유(우선순위 기준과 연결)
- 선택형 결정 질문 1~2개
- 메신저 버전 1개 + 메일 버전 1개(제목 포함)
