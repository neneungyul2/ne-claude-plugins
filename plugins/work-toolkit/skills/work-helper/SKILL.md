# 업무 도우미 (work-helper)

사용자의 상황을 7개 영역 중 하나로 분류하고, 해당 영역 스킬로 넘기기 위한 진입점이다.
영역이 분명하면 이 스킬을 거치지 않고 해당 영역 스킬을 바로 써도 된다.

## 1. 영역 판별표

| 영역 | 이럴 때 |
|---|---|
| `research-analyze` | 자료를 찾아보고 분석해야 한다 — 조사 설계, 출처 검증, 문서 비교, 경쟁사, 리뷰, 페르소나 |
| `plan-decide` | 기획하고 결정해야 한다 — 실행계획, 기획서, PRD, 개발 요청, 사업성, 선택, 우선순위, 일정 |
| `organize-deliver` | 정리해서 전달해야 한다 — 지시 해석, 메일, 회의록, 보고서, 구두보고, 이슈, 피드백, 핸드오프, 성과 |
| `write-copy` | 카피·콘텐츠 원고를 써야 한다 — 광고 카피, 소구점, 콘텐츠 구성, 제목, 랜딩·상세페이지, 카드뉴스 |
| `make-visual` | 이미지·슬라이드·영상을 만들어야 한다 |
| `data-insight` | 숫자에서 답을 찾아야 한다 — 분석 질문, 데이터 정제, 엑셀, 해석, 원인, 다음 기획 |
| `automate-work` | 반복 업무를 넘겨야 한다 — 자동화 우선순위, 반복 보고서, 맥락 고정, 정기 실행, SOP |

## 2. 절차

1. 상황 설명(또는 최근 대화 맥락)을 위 표와 대조해 영역을 정한다.
2. 두 개 이상이 애매하게 겹치면 **짧게 한 번** 되물어 확정한다.
   예: "지금 필요한 게 A) 데이터에서 원인을 찾는 것인지 B) 찾은 내용을 보고서로 정리하는 것인지?"
3. 정해지면 `${CLAUDE_PLUGIN_ROOT}/skills/<영역>/SKILL.md` 를 Read 도구로 읽고 그 지침을 따른다.
   이 파일로 되돌아올 필요는 없다.
4. 여러 영역을 순서대로 거쳐야 하는 일이면 **순서를 먼저 말해주고** 첫 영역부터 진행한다.
   예: 리뷰 분석(r-05) → 개선 과제 우선순위(p-06) → 보고 메시지(o-09)

## 3. 영역 판별이 안 될 때

7개 중 어디에도 맞지 않으면 억지로 끼워 맞추지 않는다.
`${CLAUDE_PLUGIN_ROOT}/references/output-rules.md`의 공통 규칙만 적용해 일반적인 방식으로 돕는다.

## 4. 어떤 경우에도 지키는 것

- **모르는 것은 `확인 필요`로 표시한다.** 추정으로 채우지 않는다.
- **사실과 추정을 구분한다.**
- 없는 숫자·사례·출처를 만들지 않는다.
- 이미 대화에서 파악된 정보는 다시 묻지 않는다. 빠진 것 중 꼭 필요한 것만 한 번에 묻는다.

자세한 내용은 `${CLAUDE_PLUGIN_ROOT}/references/output-rules.md`.
