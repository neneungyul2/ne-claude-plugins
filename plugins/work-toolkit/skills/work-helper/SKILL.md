# 실무 상황 도우미 (work-helper)

이 스킬은 사용자의 업무 상황을 아래 10개 CASE 중 하나로 분류하고, 해당 case 스킬 파일을 읽어 그 지침을 그대로 따르기 위한 진입점이다.

## 절차

1. 사용자의 상황 설명(또는 최근 대화 맥락)을 아래 표와 대조해 가장 맞는 CASE 번호를 정한다.
2. 두 개 이상이 애매하게 겹치면, 짧게 되물어 확정한다 (예: "지금 필요한 게 A) 우선순위 재정리인지 B) 상사에게 보낼 확인 메시지인지?").
3. CASE가 정해지면 `${CLAUDE_PLUGIN_ROOT}/skills/case-0X-xxx/SKILL.md` 파일을 Read 도구로 읽고, 그 안의 지침(확인할 정보 체크리스트 + 산출물 3종)을 그대로 따라 진행한다. 이 파일로 되돌아올 필요는 없다.
4. 10개 중 어디에도 맞지 않으면 억지로 끼워 맞추지 말고, 일반적인 방식으로 도와준다.

## CASE 판별표

| CASE | 디렉터리 | 이런 상황일 때 |
|---|---|---|
| 1 | `case-01-priority-realign` | 요구 사항/범위가 계속 바뀌는데 일정은 그대로라 우선순위를 다시 정리해야 함 |
| 2 | `case-02-clarify-ambiguous-request` | 받은 요청이 애매해서 뭘 만들어야 하는지부터 확인/정의해야 함 |
| 3 | `case-03-schedule-replan` | 일정이 밀리고 있어 작업을 다시 쪼개고 현실적인 계획(+리스크 대응)을 짜야 함 |
| 4 | `case-04-handoff-dod` | 협업 핸드오프가 반복 반려되어 "완료"의 기준(DoD)과 리뷰 SLA를 맞춰야 함 |
| 5 | `case-05-meeting-followup` | 회의는 끝났는데 결정/액션아이템이 정리 안 돼 후속 정리가 필요함 |
| 6 | `case-06-incident-report` | 버그/장애/이슈가 터져서 재현·원인·대응을 정리해 공유해야 함 |
| 7 | `case-07-stakeholder-update` | 상사/타 부서에 진행 상황이나 지원 필요 사항을 보고해야 함 |
| 8 | `case-08-feedback-reflection` | 받은 피드백이 모호해서 실행 가능한 수정 항목/계획으로 쪼개야 함 |
| 9 | `case-09-sop-documentation` | 매번 다르게 처리되는 반복 업무를 SOP/체크리스트로 표준화해야 함 |
| 10 | `case-10-performance-summary` | 내가 한 일의 성과를 근거와 함께 정리해서 공유/어필해야 함 (평가, 성과발표 등) |

## 공통 원칙 (모든 case에 적용)

- 각 case 스킬은 "먼저 확인할 정보" 체크리스트와 "만들 수 있는 산출물 A/B/C" 3종을 담고 있다. 이미 대화에서 파악된 항목은 다시 묻지 말고, 산출물 생성에 꼭 필요한데 빠진 항목만 골라 한 번에 확인한다.
- 사용자가 어떤 산출물(A/B/C)을 원하는지 불명확하면, 세 가지를 한 줄씩 요약해 골라달라고 물어본다.
- 과장하거나 없는 사실을 지어내지 말 것 — 확정/미확정을 구분해서 표현한다(특히 CASE 6, 7).
