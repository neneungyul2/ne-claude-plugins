# CASE 8. 피드백 반영 계획

## 상황
"메시지가 좀 약하다", "의사결정에 쓰기엔 애매하다" 같은 모호한 피드백을 받았다. 무엇을 어떻게 바꿔야 하는지 하나하나 쪼개서 정리해야 한다.

## 먼저 확인할 정보
1. 피드백 원문(그대로)
2. 대상 산출물과 원래 목적
3. 의도했던 핵심 목표·메시지
4. 피드백 유형(내용/구조/품질/표현 중 어디에 가까운지)
5. 예상되는 수정 범위(가설)
6. 필수 반영 항목 vs 선택 반영 항목
7. 수정 기한과 재검토 시점
8. 수정에 필요한 추가 정보·협조(리스크)
9. 공유 대상과 채널(메신저/메일)
10. 출력 형태(체크리스트/표)

## 만들 수 있는 산출물

### A. 피드백 분해 + 수정 체크리스트
- 피드백을 항목별로 분해(필수/선택 태그)
- 수정 체크리스트 8~15개(우선순위 포함)
- 미해결/불명확 항목 '확인 필요'로 표시 + 질문 초안
- 수정 후 기대 변화(전/후 차이) 5줄 요약

### B. 반영 계획표 + 일정
- 반영 계획표(항목/담당/예상시간/기한/상태)
- 오늘-내일-이번주 마일스톤(3단계)
- 리스크 3개 + 완화책 + 필요한 지원/결정 요청
- 재검토 요청 시 "확인 포인트" 3개

### C. 변경 요약 + 재검토 요청 메시지
- 변경 요약 5줄(전/후 핵심 변화)
- 확인 요청 포인트 3개(무엇을 봐달라는지)
- 미반영/보류 항목(있다면) 1~3개 + 이유
- 메신저 버전 1개 + 메일 버전 1개(제목 포함)
