# 숫자에서 답을 찾을 때

## 0. 먼저 읽을 것

${CLAUDE_PLUGIN_ROOT}/references/output-rules.md — 공통 출력 규칙. 건너뛰지 않는다.

## 1. 상황 판별

| id | 이럴 때 |
|---|---|
| d-01 | RAW 데이터는 있는데 어떤 질문을 던져야 할지 모르겠다 |
| d-02 | 날짜·항목명이 제각각이라 분석을 시작조차 못 한다 |
| d-03 | 엑셀 함수를 찾아도 내 시트에 어떻게 적용할지 모르겠다 |
| d-04 | 숫자와 그래프는 만들었는데 의미를 설명하지 못한다 |
| d-05 | 성과가 오른 건 알겠는데 무엇 때문인지 설명하지 못한다 |
| d-06 | 성과 리포트는 쓰는데 다음 기획은 또 감으로 정한다 |

## 2. 절차

1. 위 표에서 맞는 id를 고른다.
2. `${CLAUDE_PLUGIN_ROOT}/references/situations/data-insight/<id>.md` 를 Read 도구로 읽는다.
3. 그 문서의 지침을 그대로 따른다.
4. **표에 없으면** 아래 3장의 공통 원칙으로 처리한다.

## 3. 이 영역의 공통 원칙

- **데이터에 없는 값을 추정해 채우지 않는다.** 결측은 결측으로 두고 개수를 적는다.
- **원본을 바꾸지 않는다.** 정제는 사본에서 하고, 변경 내역을 남긴다.
- **관찰된 사실과 해석을 분리한다.** 같이 움직인 것이 원인은 아니다.
- **집계 기준을 항상 함께 적는다.** 기간·단위·대상·포함/제외 조건이 빠지면 숫자는 해석이 안 된다.
- 원인을 하나로 단정하지 않는다. 가설 여러 개와 각각의 검증 방법을 낸다.
- **차트·대시보드·보고서를 실제로 만드는 단계가 되면 `report-maker` 플러그인으로 넘긴다.**
  이 영역은 질문 설계·정제·해석까지다. report-maker가 없으면 표와 해석 문장까지만 내고 사용자에게 알린다.
