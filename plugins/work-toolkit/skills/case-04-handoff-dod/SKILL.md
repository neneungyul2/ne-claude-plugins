# CASE 4. 핸드오프 기준 · 완료 정의(DoD)

## 상황
완료했다고 넘긴 작업이 계속 되돌아온다. 완수 기준을 세우지 않으면 끝나지 않는 무한 수정의 굴레에 빠진다.

## 먼저 확인할 정보
1. 산출물 정의 — 무엇을 핸드오프하는지
2. 참여자와 역할 — 요청자/수행자/리뷰어/승인자
3. 핸드오프 흐름(단계) 정의
4. 입력물 기준 — 시작/검수에 필요한 권한·자료
5. 출력물 기준 — 형식/링크/버전
6. 완료 정의 기준(품질/테스트/문서화, 체크 가능한 형태로)
7. 검수·리뷰 방식과 응답 시간(SLA)
8. 반려 기준(명확한 조건)
9. 핸드오프 기한과 커뮤니케이션 채널
10. 출력 형태(체크리스트/표)

## 만들 수 있는 산출물

### A. DoD 체크리스트 (반려 기준 포함)
- DoD 체크리스트 10~20개(단계별: 작업/리뷰/승인/인수)
- 반려 기준 5~10개(명확한 조건)
- 증거(스크린샷/로그/링크) 요구 항목 표기

### B. 인수인계 문서 + 메시지 템플릿
- 인수인계 템플릿: 목적/범위/변경 사항/사용법/주의/검증/다음 액션
- 핸드오프 메시지(메신저) 1개 + 메일 버전 1개
- 리뷰어가 확인해야 할 포인트 5개(체크 질문 형태)

### C. 리뷰/승인 운영 규칙(SLA)
- 리뷰 SLA 제안(초안/최종, 응답/수정 기한)
- 수정 라운드 규칙(몇 회, 무엇이 '최종'인지)
- 긴급 이슈 발생 시 우선 처리 룰
- 합의 공지 메시지(메신저) 1개 + 요약 5줄
