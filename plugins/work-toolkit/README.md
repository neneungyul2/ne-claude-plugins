# work-toolkit

실무에서 막히는 순간에 꺼내 쓰는 업무 도구함.
조사·기획·보고·카피·이미지·데이터·자동화 **7개 영역 52개 상황**을 다룬다.

## 쓰는 법

그냥 말하면 된다.

```
"이 엑셀에서 뭘 봐야 할지 모르겠어"
"회의록 정리해줘"
"그래서 결론이 뭐냐는 말을 들었어"
"이 용어로 카피 좀 뽑아줘"
"반복 업무 자동화하고 싶은데 뭐부터?"
```

어느 영역인지 애매하면 `work-helper`가 먼저 받아 판별한다.

## 구조

```
work-toolkit/
├── skills/
│   ├── work-helper/          진입점. 영역 판별 (애매할 때만)
│   ├── research-analyze/     찾아보고 분석할 때      6상황
│   ├── plan-decide/          기획하고 결정할 때      9상황
│   ├── organize-deliver/     정리하고 전달할 때     11상황
│   ├── write-copy/           카피와 콘텐츠를 쓸 때   8상황
│   ├── make-visual/          이미지·슬라이드·영상    6상황
│   ├── data-insight/         숫자에서 답을 찾을 때   6상황
│   └── automate-work/        반복 업무를 넘길 때     6상황
└── references/
    ├── output-rules.md               공통 출력 규칙
    └── situations/<영역>/<id>.md      상황별 상세 52개
```

**스킬은 영역으로 묶고, 상황은 참조 문서로 세분화한다.**
영역 스킬이 상황 판별표를 갖고 해당 참조 문서를 읽어 수행하므로, 상황이 늘어도 스킬 수는 늘지 않는다.
스킬 45개를 만들면 description이 서로 겹쳐 자동 라우팅이 오히려 망가진다.

판별표에 없는 상황은 플러그인 밖으로 빠지지 않고 **각 영역의 공통 원칙으로 받아낸다.**

## 어떤 상황에서도 지키는 것

`references/output-rules.md`에 정리되어 있다.

- **모르는 것은 `확인 필요`로 표시한다.** 추정으로 채우지 않는다.
- **사실과 추정을 구분한다.**
- 없는 숫자·사례·출처를 만들지 않는다.
- 과장하지 않는다. 책임을 특정 사람에게 돌리는 표현을 쓰지 않는다.
- 상황 문서의 출력 섹션 번호와 제목을 그대로 쓴다. 같은 상황을 두 번 돌려도 결과 모양이 같아야 한다.

## 다른 플러그인과의 경계

`data-insight`와 `make-visual`은 **무엇을 볼지, 어떻게 해석할지, 어떻게 설명할지**까지 다룬다.
차트·대시보드·보고서 문서를 실제로 만드는 단계가 되면 **`report-maker`** 로 넘긴다.

`automate-work`의 a-03에서 만든 업무 맥락 문서가 반복해서 쓰인다면,
그것을 스킬이나 플러그인으로 만들어 이 마켓플레이스에 추가하는 것이 다음 단계다.

## 출처

각 상황의 "먼저 확인할 것 · 출력 구조"는 아래 자료의 구성을 참고해 스킬 형태로 재구성한 것이다.
프롬프트 문장을 그대로 옮기지 않았고, 사내 실무에 맞게 다시 작성했다.

- 에이블런(ABLEARN) 〈실무자를 위한 프롬프트 팩〉 (정대리 시리즈, CASE 1~10)
  — v0.1.0의 10개 case 구성. 현재는 `plan-decide`·`organize-deliver`·`automate-work`에 흡수
- 퍼블리(Publy) 〈직장인을 위한 AI 프롬프트 45 — 업무 상황별 실전편〉
  — 7개 영역 구분과 45개 상황

두 자료 모두 인용 시 출처 명기를 요구한다. **사내 용도로만 사용한다.**
