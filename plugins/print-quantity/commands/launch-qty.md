description: 신간 제작 부수를 검토한다 (5단계 전부)
argument-hint: [도서명 또는 제작 계획서 첨부]
---

신간 제작 수량 검토를 진행한다. 요청: $ARGUMENTS

**대상이 이미 출고 실적이 있는 기간본이면 여기서 멈추고 `/reprint-qty`로 안내한다.**
경쟁서에서 역산하는 이 흐름은 자사 실적이 없는 신간 전용이다.

**5단계를 전부 돈다. 하나도 건너뛰지 않는다.**

```
1) define-segment        세그먼트·권별 위계 확정          ← 데이터를 열기 전
2) size-market           경쟁서 전수 조회 → 목차 검증 → TAM/SAM   ← 사용자 확인
3) derive-coefficients   자사 벤치마크에서 계수 산출 + 검산
4) estimate-demand       점유율 → 첫해 수요 → 채널 분해 → 부수   ← 사용자 확인
5) build-qty-report      HTML 렌더링 + 수치 정합 검사
```

각 단계는 해당 SKILL.md를 Read로 읽고 그 지침을 따른다.
`${CLAUDE_PLUGIN_ROOT}/skills/<이름>/SKILL.md`

**사용자 확인은 두 곳이다. 둘 다 글자로 한다.**

- 2단계 — **경쟁서 목록.** 여기가 틀리면 뒤가 전부 틀린다
- 4단계 — **목표 점유율 기준값.** 부수를 좌우하는 유일한 가정이다

HTML을 먼저 만들어놓고 확인받지 않는다. 만들면 애착이 생겨 틀렸어도 못 버린다.

**수정 요청이 오면 어디까지 되돌아갈지부터 가른다.**

| 바뀌는 것 | 되돌아갈 곳 |
|---|---|
| 경쟁서 포함·제외, 분류 | 2단계. 계수는 그대로 |
| 벤치마크, 조회 기간, 채널 정의 | 3단계 |
| 목표 점유율, 초도 배본, 초판 비중 | 4단계 |
| 문구, 배치, 색 | 5단계. 본문만 Edit |

**계수를 바꾸면 두 도서를 함께 검토 중일 때 양쪽에 같이 적용한다.**
한쪽만 바꾸면 산식이 비대칭이 되고, 반드시 지적받는다.
