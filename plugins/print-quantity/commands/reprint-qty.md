기간본 재제작 수량 검토를 진행한다. 요청: $ARGUMENTS

**5단계를 전부 돈다. 하나도 건너뛰지 않는다.**

```
1) define-segment    세그먼트 + 품목코드·개정 예정일·리드타임 확정   ← 데이터를 열기 전
2) size-market       경쟁서 조회 → 연도별 추이 → 자사 점유율        ← 사용자 확인
3) project-demand    창고 가려 가용재고 → g·계절지수 → 원인 판정 → 수요 곡선
4) size-reprint      소진 시점 → 커버 기간 → 수량 → 개정 상한       ← 사용자 확인
5) build-qty-report  HTML 렌더링 + 수치 정합 검사
```

각 단계는 해당 SKILL.md를 Read로 읽고 그 지침을 따른다.
`${CLAUDE_PLUGIN_ROOT}/skills/<이름>/SKILL.md`

**시작 전에 반드시 확인하는 것 — 없으면 물어본다.**

| | 없으면 |
|---|---|
| 개정·폐간 예정일 | **"없음"까지 확인받는다.** 이 하나로 수량이 절반이 된다 |
| 제작 리드타임 | 1.5개월로 두되 미확인이라고 적는다 |
| 미입고분 | 데이터에 없다. 물어야 안다 |

**2단계를 건너뛰지 않는다.** 출고가 줄어든 원인을 모르면 줄어든 추세를 그대로 미래에 투영하게 된다.
시장이 늘었는데 자사만 줄었으면 **원인 확인 전까지 진행하지 않는다.**

**사용자 확인은 두 곳이다. 둘 다 글자로 한다.**

- 2단계 — **경쟁서 목록과 자사 점유율 추이.** 여기가 틀리면 원인 판정이 뒤집힌다
- 4단계 — **커버 기간과 개정 예정일.** 수량을 좌우하는 두 값이다

HTML을 먼저 만들어놓고 확인받지 않는다.

**수정 요청이 오면 어디까지 되돌아갈지부터 가른다.**

| 바뀌는 것 | 되돌아갈 곳 |
|---|---|
| 경쟁서 포함·제외, 분류 | 2단계 |
| 창고 분류, 품목코드, 조회 구간 | 3단계 |
| 커버 기간, 개정 예정일, 리드타임, 안전재고 | 4단계 |
| 문구, 배치, 색 | 5단계. 본문만 Edit |

**여러 종이면 종별로 따로 계산하고 따로 반올림한다.** 묶어 찍는 판단은 제작팀 소관이다.
