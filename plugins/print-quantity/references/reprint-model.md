# 기간본 재제작 모델

신간과 기간본은 **정반대 방향으로 푼다.**

| | 신간 | 기간본 |
|---|---|---|
| 자사 실적 | 없다 | **있다. 이게 1차 근거다** |
| 방향 | 경쟁서 시장에서 역산 (top-down) | 자사 출고 추세에서 투영 (bottom-up) |
| 정하는 것 | 첫해 얼마나 팔릴까 | **언제 떨어지고, 언제까지 버틸 만큼 찍을까** |
| 시장 조회 | 시장 규모를 잡으려고 | **추세가 꺾인 원인을 가리려고** |
| 상한 | 없다 | **개정·폐간 예정일. 넘기면 사장 재고가 된다** |

기간본에서 시장 조회를 빼지 않는다. 출고가 줄었을 때 **시장이 줄어든 것인지 우리가 뺏긴
것인지**를 가르지 못하면, 줄어든 추세를 그대로 미래에 투영해 계속 과소·과대 제작하게 된다.

## 1. 산식 전체

```
가용재고       = Σ 재고수량 (정품 창고만)
월별 수요 D(m) = 기준 연간 수요 × g^(경과연차) × s(m)
소진 예상월    = 누적 D(m)가 가용재고를 넘어서는 달
발주 마감일    = 소진 예상월 − 리드타임 L

수요 기준 수량 = Σ D(T ~ T+L+C) + 안전재고 − 가용재고
잔여 수명 상한 = Σ D(T ~ E) × r − 가용재고          (E = 개정·폐간 예정)

제작 수량      = min(수요 기준 수량, 잔여 수명 상한) → 로트 반올림
```

`T` 현재 · `L` 제작 리드타임 · `C` 커버 기간 · `E` 구판 판매 종료 시점 · `r` 개정 전 둔화율.

**상한이 수요 기준보다 낮으면 그 사실을 결론에 쓴다.** "수요로는 6,000부지만 개정 예정이라
3,000부로 줄였다"가 보고의 핵심이지, 숨기면 왜 이 숫자인지 설명되지 않는다.

## 2. 가용재고 — 창고를 가려야 한다

`raw.sap_inventory_wh`는 최신 `basedate` 기준 품목 × 창고별 `재고수량`을 준다.
**창고가 36개이고 팔 수 없는 재고가 섞여 있다.** 전부 더하면 소진 시점이 한참 뒤로 밀린다.

| 처리 | 창고 (2026-09 기준 이름 패턴) |
|---|---|
| **포함** | `북마을(…정품)`, `북마을(수학/출판국어/대학수험 등 정품 계열)`, `영진(…)`, `유아(정품)`, `쿠팡`, `본사(정품)` |
| **제외** | `폐기`, `반품`, `반품미분류`, `수리본`, `제작처(수리본)`, `수출`, `세트` |

**창고 코드를 하드코딩하지 않는다.** 이름으로 런타임 조회해 분류하고, 어떤 창고를 넣고 뺐는지
목록째로 보고서 부록에 적는다. 창고 구성은 바뀐다.

```sql
SELECT 창고코드, 창고이름, SUM(재고수량) qty
FROM raw.sap_inventory_wh
WHERE basedate = (SELECT MAX(basedate) FROM raw.sap_inventory_wh)
  AND 품목코드 IN (<대상>)
GROUP BY 1,2 ORDER BY qty DESC
```

`세트` 창고는 합본 품목코드로 따로 잡힌다. 세트 구성품이면 세트 판매분도 수요에 넣어야 하므로
**세트 품목코드를 먼저 확인**한다. 빠뜨리면 수요를 통째로 과소 추정한다.

### 미입고분(제작 진행 중)은 데이터에 없다

SAP 생산 발주 잔량을 담은 테이블은 없다. **제작팀에 물어 확정값으로 받는다.**
진행 중 물량이 있으면 가용재고에 입고 예정일과 함께 더한다. 추정하지 않는다.

## 3. 수요 곡선 — 세 조각으로 만든다

### ① 기준 연간 수요

직전 12개월 SAP 출고. `raw.sap_sales`를 쓴다.

**추세용과 소진 시뮬레이션용의 기준이 다르다.**

| 용도 | 기준 | 이유 |
|---|---|---|
| 추세·계절지수 | 총출고 (`quantity > 0`만) | 반품이 섞이면 성수기 모양이 무너진다 |
| 재고 소진 시뮬레이션 | 순출고 (반품 차감) | 반품은 재고로 돌아온다. 총출고로 보면 소진이 빨라 보인다 |

두 값을 **둘 다 내서 보고서에 나란히 적는다.** 차이가 크면(15% 이상) 반품률이 높은 품목이고,
안전재고를 낮춰 잡아야 한다.

### ② 노후화율 g

```
g = 최근 12개월 총출고 ÷ 직전 12개월 총출고
```

3개년 이상 있으면 연도별로 뽑아 곡선을 본다. 참고서는 **출시 2년 차가 정점이고 3년 차부터
반토막**이 나는 패턴이 흔하다 (`benchmarks.md` 참조). 직전 1년만 보면 이 변곡을 놓친다.

`g`를 그대로 미래에 곱하기 전에 **2단계의 시장 조회 결과와 대조한다.**

| 시장 | 자사 | 판정 | `g` 처리 |
|---|---|---|---|
| 유지 | 감소 | 점유율 이탈 | 그대로 쓴다. 경쟁 신간이 원인이면 더 낮춘다 |
| 감소 | 감소 | 시장 축소 | 그대로 쓴다. 회복 가정을 넣지 않는다 |
| 증가 | 감소 | 유통·노출 문제 | **그대로 쓰지 않는다.** 원인을 확인하기 전까지 진행하지 않는다 |
| 감소 | 유지 | 점유율 상승 | 시장 감소분만큼 `g`를 낮춰 보수적으로 본다 |

### ③ 계절지수 s(m)

```
s(m) = 해당 월 출고 ÷ 연 출고     (최근 3개년 평균, Σ s(m) = 1)
```

**기간본에서 가장 중요한 계수다.** 소진 시점이 성수기 직전이냐 직후냐로 결론이 갈린다.
연평균으로 뭉개면 성수기 직전에 품절나는 품목을 못 잡는다.

3개년이 안 되면 있는 만큼 쓰되 표본 수를 보고서에 적는다. 개정·리뉴얼로 품목코드가 바뀐
이력이 있으면 **구품목코드 출고를 이어 붙여** 계절성을 본다. 품목코드만 보면 1년치밖에 없다.

## 4. 리드타임 L과 안전재고

| 값 | 기본 | 근거 |
|---|---|---|
| `L` 제작 리드타임 | **1.5개월** | 재판 기준. 건별로 제작팀에 확인해 바꾼다 |
| 안전재고 | **리드타임 기간 수요 1회분** | 재발주 한 사이클을 버틴다 |

`L`은 확인 가능한 값이다. 추정해서 쓰지 말고 물어본다. 성수기 직전 발주는 제작처가 밀려
리드타임이 길어진다. **소진 예상월이 성수기와 겹치면 `L`을 1.5배로 보고 유의사항에 적는다.**

반품률이 높은 품목(총출고 대비 순출고 15% 이상 차이)은 안전재고를 0.5회분으로 낮춘다.
반품이 실질적인 완충재고 역할을 하기 때문이다.

## 5. 커버 기간 C — 성수기로 끊는다

**개월 수를 먼저 정하지 않는다.** 다음 성수기가 끝나는 달까지를 덮는 것이 기본이다.

```
C = (다음 성수기 종료월 − 입고 예정월) + 1
```

성수기는 계절지수에서 나온다. 카테고리별로 다르다 — 신학기(1~3월), 시험 주기(12·1~2월·7월).

| 상황 | 커버 기간 |
|---|---|
| 기본 | 다음 성수기 종료까지 |
| 회전이 빠르고 로트가 작다 | 짧게. 재발주 횟수를 늘린다 |
| 개정 예정이 있다 | **5절의 상한이 먼저 걸린다** |
| 폐간 검토 중 | 성수기 하나만 덮는다. 그 뒤는 찍지 않는다 |

보고서에서는 **슬라이더로 조정**할 수 있게 한다. 커버 기간이 수량을 좌우하는 유일한 선택값이다.

## 6. 잔여 수명 상한 — 개정·폐간

**개정·폐간 예정일 `E`는 반드시 묻는다.** 없으면 "없음"이라고 확인받고 진행한다.
"모른다"로 넘어가지 않는다. 이 하나로 수량이 절반이 된다.

```
잔여 수요 = Σ D(T ~ E) × r
```

`r` = 개정 전 둔화율, **기본 0.9**. 개정이 공지되면 채널이 구판 발주를 줄이므로 마지막 몇 달의
수요가 계획보다 덜 나간다. 개정 공지가 이미 나갔으면 0.8까지 낮춘다.

제작 수량이 상한에 걸리면 **사장 예상 재고를 계산해 보고서에 적는다.**

```
사장 예상 재고 = 가용재고 + 제작 수량 − Σ D(T ~ E)
```

0보다 크면 그 부수만큼 폐기 위험이다. 결론 옆에 그대로 적는다. **상한에 걸렸다는 사실을
숨기고 수량만 적으면 "왜 이것밖에 안 찍느냐"는 질문에 답할 수 없다.**

E가 없는 품목이라도 **교육과정 개편·수능 체제 변경 시점**은 사실상의 상한이다. 확인한다.

## 7. 로트 반올림

```
산출값 → 백 단위 반올림 → 최소 로트 하한 적용 → 천 단위 반올림
```

신간과 같은 2단계 반올림을 쓴다. 이유도 같다 — 화면 표시값과 결과가 어긋나지 않게 한다.
`Math.round`(0.5 올림) 기준으로 검산한다. 파이썬 `round`는 짝수로 내려 경계값에서 틀린다.

**최소 로트는 실측한다.** 품목의 과거 생산입고 이력에서 실제 로트 단위를 본다.

```sql
SELECT docdate, SUM(생산입고수량) q
FROM mart.sap_inventory_daily
WHERE itemcode IN (<대상>) AND 생산입고수량 > 0
GROUP BY 1 ORDER BY 1 DESC
```

생산입고 실적은 계획 부수보다 1~3% 많게 잡힌다(과부수). **계획 부수를 되물을 때 이 차이를
감안**하고, 이력에서 읽은 값을 그대로 "지난 제작 부수"로 보고하지 않는다.

제작 이력은 그 자체로 근거가 된다. 지난 로트가 언제 몇 부였고 몇 개월 만에 소진됐는지를
보고서에 한 줄로 적으면 이번 수량의 타당성이 바로 보인다.

## 8. 여러 종을 함께 볼 때

시리즈 단위로 요청이 들어온다. **종별로 따로 계산하고 따로 반올림한다.**

- 소진 시점이 종마다 다르다. 한 번에 묶어 찍으면 늦은 종은 재고가 오래 남는다
- 묶어 찍어 단가를 낮추는 판단은 제작팀 소관이다. **우리는 종별 필요량과 소진 시점을 주고,
  묶음 여부는 제작팀이 정하게 한다.** 우리가 묶어서 제안하면 근거가 흐려진다
- 다만 소진 시점이 1개월 안에 몰려 있으면 그 사실을 표시한다. 묶을 근거가 된다

## 9. 자주 틀리는 것

| 증상 | 원인 |
|---|---|
| 소진 시점이 터무니없이 멀다 | 폐기·반품 창고 재고를 합쳤다 |
| 수요가 실제보다 적다 | 세트 품목코드 판매분이 빠졌다 |
| 성수기 직전에 품절났다 | 연평균으로 수요를 깔았다. 계절지수를 안 썼다 |
| 계절성이 1년치밖에 안 나온다 | 개정으로 품목코드가 바뀌었다. 구품목코드를 이어 붙인다 |
| 재고가 계속 남는다 | 개정 예정일을 확인하지 않고 커버 기간으로만 찍었다 |
| 추세가 꺾인 이유를 설명 못 한다 | 시장 조회를 건너뛰었다 |
