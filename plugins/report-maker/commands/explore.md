탐색형 모드로 진행한다. 요청: $ARGUMENTS

**결론을 내미는 산출물이 아니다.** 독자가 축을 스스로 바꿔가며 보는 틀을 만든다.

```
1) frame-explore    축(axis)·데이터 그레인·패널 후보 합의     ← 데이터를 열기 전
2) load-data        정규화. 단, 그레인 전체를 긴 형식으로 남긴다
3) plan-explore      탐색 스펙 + 패널 배치 설계
4) build-explore     공용 계산 엔진 위에 패널 렌더링
5) verify-report     소스 검사 → 렌더 검사 → 축 조합 검사
```

각 단계는 해당 SKILL.md를 Read로 읽고 그 지침을 따른다.
`${CLAUDE_PLUGIN_ROOT}/skills/<이름>/SKILL.md`

**`action_title`·`key_takeaway`·`weight: primary`는 이 파이프라인에 없다.**
`/report`의 대응 필드를 억지로 채우려 하지 않는다 — `references/report-types.md` §1이
왜 탐색형만 파이프라인이 따로인지 설명한다.

**사용자 확인은 두 곳이다. 둘 다 글자로 한다.**

- 1단계 — **축**. 무엇을 바꿔볼 수 있게 할지, 데이터를 보기 전에 정한다
- 3단계 — **패널 배치**. 실제 패널이 들어간 모습을 보이고 동의를 받는다

**수정 요청이 오면 무엇을 다시 만들지부터 가른다.**

| 층 | 예 | 한다 |
|---|---|---|
| **축·그레인** | 축 추가·제거, 그레인 단위 변경 | 1단계로 되돌아간다 |
| **패널** | 패널 종류·배치 변경, 계산 로직 오류 | 3단계로 되돌아가 스펙을 고친다 |
| **표현** | 라벨 위치, 색, 마진 | 본문만 `Edit` |

이 화면이 실은 매번 같은 자리에 데이터만 갈아끼우는 것이라는 게 드러나면
탐색형이 아니라 점검형이다 — `/report`로 다시 시작한다.
