기존 산출물을 새 데이터로 갱신한다. 대상: $ARGUMENTS

**구성을 바꾸지 않는다.** 이번 데이터가 흥미롭다고 섹션을 추가하지 않는다 —
독자가 매번 화면을 새로 익혀야 한다. 흥미로운 것이 생겼으면 그건 **별도의 진단 리포트**다.

```
기존 report-spec.json 읽기 → 데이터만 갈아끼움 → 결론·라벨 다시 계산 → 렌더 → 검수
```

1. 기존 `report-spec.json`을 읽는다. 없으면 산출물에서 **구성을 복원하고 사용자에게 확인받는다**
2. `load-data`로 새 데이터를 정규화한다. **기준(`basis`)이 이전과 같은지 반드시 확인한다** —
   기준이 바뀌었는데 갱신하면 이전 회차와 비교할 수 없는 숫자가 나란히 놓인다
3. **다시 계산해야 하는 것** — `key_takeaway`, 각 `action_title`, `so_what`, KPI의 `delta`,
   축 범위, 각주의 기간·추출 시각. 숫자만 바꾸고 결론 문장을 두면 **거짓말이 된다**
4. `build-html` → `check_html.py` + `lint_render.py`

**유형에 따라 하는 일이 다르다** (`${CLAUDE_PLUGIN_ROOT}/references/report-types.md`).

| | 갱신할 때 |
|---|---|
| `watch` 감시 | `.report-watch-rules.json`의 룰을 다시 평가한다. 걸린 것만 올린다. **아무것도 안 걸리면 "특이사항 없음"과 무엇을 확인했는지**를 쓴다. `${CLAUDE_PLUGIN_ROOT}/references/watch-thresholds.md` |
| `track` 추적 | 기준선은 그대로 두고 현재 위치만 옮긴다. **"이 속도면 어떻게 되는가"를 다시 계산한다** |
| `diagnostic` 진단 | 원래 한 번 읽는 문서다. 갱신 대상이 아니다 — 새 기간이면 새 진단이고, `/report`로 간다 |
| `choice` 선택 | 위와 같다. 결정이 끝난 판단 기록이다 |

- 이전 회차 파일을 덮어쓰지 않는다. 파일명에 기간을 넣는다
- 임계값이나 구성을 바꿨으면 **각주에 바꾼 날과 무엇을 바꿨는지** 남긴다.
  조용히 바뀌면 과거 회차와 비교할 수 없게 된다
