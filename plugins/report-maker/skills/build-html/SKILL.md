# HTML 렌더링 (build-html)

`report-spec.json`을 **HTML 파일 하나**로 만든다. 스펙에 없는 결론을 새로 만들지 않는다.

## 0. 먼저 읽을 것

- `${CLAUDE_PLUGIN_ROOT}/references/design-rules.md`
- `${CLAUDE_PLUGIN_ROOT}/references/html-template.html` — 토큰·레이아웃·SVG 차트 기본형

## 1. 원칙

- **단일 파일.** 외부 CSS·JS·폰트·이미지를 불러오지 않는다. 사내망 밖이나 오프라인에서도 열려야 한다.
- **차트는 인라인 SVG.** 차트 라이브러리를 CDN에서 불러오지 않는다. 스펙의 `data.rows`로
  좌표를 계산해 `<svg>`를 직접 생성한다.
- **디자인 토큰만 사용.** 템플릿의 CSS 변수 밖 색을 쓰지 않는다.
- 반응형. 모바일 폭(~400px)에서도 가로 스크롤이 생기지 않아야 한다. 표와 넓은 차트만
  `overflow-x: auto` 컨테이너 안에 둔다.
- 라이트/다크 모두에서 읽힌다. 템플릿의 `prefers-color-scheme` 블록을 유지한다.

## 2. 레이아웃

```
┌──────────────────────────────────────────┐
│ 제목            기준: 순출고 · 8월 · 부  │  ← 기준 항상 상단 노출
├──────────────────────────────────────────┤
│ ■ 헤드라인 (가장 크게, 좌측)             │
│   요약 3줄 (report만)                    │
├──────────────────────────────────────────┤
│ ex1 action_title                         │
│     [차트]              so_what          │
│     각주 4요소                            │
├──────────────────────────────────────────┤
│ ex2 ...                                   │
├──────────────────────────────────────────┤
│ 공통 각주 · 확인 필요 항목                │
└──────────────────────────────────────────┘
```

- 좌상단에 결론, 아래로 근거. 순서를 바꾸지 않는다.
- exhibit은 스펙 배열 순서 그대로. 재배치하지 않는다.
- KPI 여러 개는 한 줄에 묶되 4개를 넘기지 않는다.

## 3. 차트 생성 규칙

| chart | 구현 |
|---|---|
| `bar`, `bar_sorted` | 세로 막대. **y축 0 시작 필수**. 항목 8개 초과면 가로 막대 |
| `line` | 점 표시 + 선. 계열 4개 이하. 끝점에 계열명 직접 라벨 (범례 대신) |
| `stacked_bar`, `stacked_bar_100` | 계열 5개 이하. 순서를 고정하고 범례를 스택 순서와 맞춘다 |
| `stacked_area` | 계열 4개 이하 |
| `dot_plot` | 항목 많을 때 막대 대신 |
| `scatter` | 축 라벨에 단위 필수 |
| `histogram` | 구간 수와 구간 폭을 각주에 명시 |
| `diverging_bar` | 0 기준선을 굵게 |
| `waterfall` | 증가/감소 색 구분, 합계 막대는 중립색 |
| `bullet` | 실적 막대 + 목표 세로선 |
| `kpi` | 값 + 라벨 + 전기 대비(방향색) |
| `table` | 우측 정렬 수치, 천단위 구분, 강조행만 배경색 |

금칙(`pie`, `donut`, 3D, 이중 Y축, 잘린 축, 무지개 팔레트)이 스펙에 있으면 **렌더링하지 않고**
대안 차트로 바꾼 뒤 사용자에게 알린다.

## 4. 인터랙션

마지막에 붙인다. 없어도 산출물이 성립해야 한다.

- **툴팁** — 기본. 값·라벨·단위를 보여준다.
- **필터** — "이 화면을 보고 바로 이어서 나올 질문"에만 붙인다. 기간·채널 정도.
  필터를 붙이면 현재 필터 상태를 화면에 글자로 표시한다.
- 정렬 토글, 다운로드 버튼 등은 요청이 있을 때만.
- `localStorage`는 쓰지 않는다. 필요하면 페이지 내 변수로만 상태를 유지한다.

## 5. 사외 반출 대비

산출물을 사외로 보낼 가능성이 있으면 사용자에게 확인하고, 원하면 비밀번호 보호를 안내한다.

- 권장: [StatiCrypt](https://github.com/robinmoisson/staticrypt) — HTML 하나를 암호화된 HTML 하나로 바꿔준다.
- 자동으로 적용하지 않는다. 비밀번호를 임의로 정하지 않는다.
- 보호를 적용하면 원본과 암호화본을 모두 남긴다.

## 6. 파일명과 전달

- 파일명: `<주제>_<기간>_<기준>.html` (예: `채널별출고_2026-08_순출고.html`)
- 작업 폴더에 저장하고 사용자에게 전달한다.
- 다시 열어볼 대시보드·트래커·현황판이면 링크로 남길 수 있게 아티팩트 게시를 제안한다.
  일회성 확인용이면 파일 전달로 끝낸다.

## 7. 검수

전달 전에 확인한다.

- [ ] 외부 리소스 참조가 0건인가 (`http://`, `https://`, `src=`, `@import` 검색)
- [ ] 모든 막대 차트가 0에서 시작하는가
- [ ] 모든 exhibit에 각주 4요소가 있는가
- [ ] 상단에 기준이 표시되는가
- [ ] 400px 폭에서 가로 스크롤이 없는가
- [ ] `open_questions`가 비어 있지 않으면 화면에 표시되는가
- [ ] 스펙의 `action_title`과 화면 제목이 글자 그대로 일치하는가
