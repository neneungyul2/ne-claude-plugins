# 차트 규칙 (chart-rules)

차트는 취향이 아니라 **질문 유형**으로 고른다.

---

## 1. question_type → chart 매핑

`skills/plan-report/references/spec-schema.md` 4장과 **동일한 표**다. 한쪽만 고치지 않는다.

| question_type | 질문 | 기본 chart | 대안 | 쓰지 말 것 |
|---|---|---|---|---|
| `trend` | 시간에 따라 어떻게 변했나 | `line` | `area` | 막대(구간 12개 초과 시) |
| `trend_many` | 계열이 많은데 각각의 추이를 봐야 하나 | `small_multiples` | `line`(강조 1개) | 스파게티 선그래프 |
| `change_2point` | **두 시점 사이에 무엇이 오르고 내렸나** | `slopegraph` | `dot_plot`, `diverging_bar` | 막대 두 묶음 |
| `comparison` | 어느 쪽이 큰가 | `bar` | `dot_plot` | 파이 |
| `ranking` | 순위가 어떻게 되나 | `bar_sorted` | `dot_plot` | 정렬 안 된 막대 |
| `composition` | 무엇이 전체를 구성하나 | `stacked_bar` | `stacked_bar_100` | 파이, 도넛 |
| `headline_number` | 전할 숫자가 한두 개다 | `simple_text` | `kpi` | 두 값짜리 막대 차트 |
| `composition_2d` | 두 축으로 동시에 쪼개면 어디에 몰려 있나 | `marimekko` | `heatmap` | 막대 두 개 나란히 |
| `bridge` | A에서 B로 가는 동안 무엇이 더하고 뺐나 | `waterfall` | `bar` | 시작·끝만 있는 막대 |
| `distribution` | 어떻게 흩어져 있나 | `histogram` | `box_plot` | 평균 하나만 표시 |
| `correlation` | 두 값이 같이 움직이나 | `scatter` | — | 이중 Y축 선그래프 |
| `deviation` | 기준 대비 얼마나 벗어났나 | `diverging_bar` | `bullet` | 일반 막대 |
| `part_to_whole_time` | 구성이 시간에 따라 변했나 | `stacked_area` | `stacked_bar` | 파이 여러 개 |
| `flow` | 어디서 어디로 이동했나 | `sankey`(항목 ≤6) | `waterfall` | — |
| `geo` | 어느 지역인가 | `choropleth` | `bar_sorted` | 지역명 막대만 (분포가 안 보인다) |
| `single_value` | 지금 값이 얼마인가 | `kpi` | — | 게이지, 도넛 |
| `detail` | 정확한 숫자를 봐야 함 | `table` | — | 차트 |

매핑에 없는 질문이면 억지로 끼우지 말고 **무엇을 알고 싶은지 되묻는다.**
새 유형이 반복해서 나오면 이 표와 spec-schema를 함께 갱신한다.

## 1-1. 인코딩 서열 — 주장을 만드는 값이 가장 강한 채널을 갖는다

차트 종류를 골랐다고 끝이 아니다. **그 차트 안에서 어느 값이 어느 채널에 실리는지**가 남는다.
여기서 대부분의 실패가 나온다 — 차트는 맞는데 정작 하고 싶은 말이 작은 글씨로만 있다.

사람이 정확히 읽는 순서 (Cleveland & McGill):

```
위치(공통 축)  >  길이  >  각도·기울기  >  면적  >  농담·채도  >  색상  >  텍스트
   가장 정확                                                      가장 부정확
```

**규칙 — `action_title`의 주장을 만드는 값이 `x` 또는 `y`에 있어야 한다.**

스펙의 `encoding.claim`에 그 필드명을 적는다. 판정은 기계적이다.

| 상태 | 판정 |
|---|---|
| `claim`이 `encoding.x` 또는 `y`다 | 통과 |
| `claim`이 `series`(색)에만 있다 | 경고 — 색으로는 크기를 못 읽는다 |
| `claim`이 값 라벨·툴팁에만 있다 | **반려** — 차트를 바꾸거나 축을 바꾼다 |
| `claim`을 못 적겠다 | `action_title`이 이 차트에서 안 나오는 것이다. 질문으로 되돌아간다 |

전형적인 실패: 막대 길이는 *건수*인데 제목은 *건당 효율*을 말한다.
건당 효율이 주장이면 **건당 효율이 막대 길이여야 하고**, 건수는 정렬 순서나 툴팁으로 내린다.

부차적인 값은 아래 채널로 내린다 — 순서대로 약해진다.

| 값의 역할 | 채널 |
|---|---|
| 주장 | `x` / `y` (위치·길이) |
| 주장을 나누는 기준 | `series` (색). **4계열 이하** |
| 규모·신뢰도 보조 | 마커 크기, 선 굵기 |
| 참고 수치 | 값 라벨 |
| 원자료 | 툴팁, 드릴다운 |

## 2. 금칙과 이유

| 금칙 | 왜 | 대신 |
|---|---|---|
| **파이 차트** | 사람은 각도를 정확히 비교하지 못한다. 3개를 넘으면 순위조차 안 읽힌다 | `bar_sorted` |
| **도넛 차트** | 파이의 문제에 가운데 구멍이 추가된 것 | `bar_sorted`, `stacked_bar_100` |
| **3D 효과** | 원근 때문에 앞쪽 값이 커 보인다. 값을 왜곡한다 | 2D |
| **이중 Y축** | 어느 축으로 읽을지 판독에 시간이 든다. 또 **없는 상관관계를 암시한다** | ① 두 번째 축을 없애고 **데이터에 직접 라벨** ② 그래프를 **세로로 분리**하고 y축을 각자 왼쪽에, **x축은 공유** |
| **잘린 축** | 막대 길이가 곧 값인데 길이를 잘라내면 차이가 부풀려진다 | 막대는 `y_zero: true`. 미세 변화를 봐야 하면 선그래프나 증감률 차트 |
| **스파게티 선그래프** | 선이 얽히면 한 계열도 따라갈 수 없다 | 3전략 (아래 §8) |
| **무지개 팔레트** | 색 순서가 값 순서와 무관해 순위가 잘못 읽힌다 | 단색 계조 + 강조 1색 |
| **게이지** | 면적을 크게 차지하고 값 하나만 전달한다 | `kpi` 숫자 |
| **워드클라우드** | 글자 길이가 빈도로 오독된다 | `bar_sorted` |
| **묶은 항목을 각주로만 설명** | 클릭해서 열어볼 수 없으면 그 데이터는 사라진 것이다 | `group_detail` + 모달 |
| **축약어를 설명 없이 쓰기** | 읽는 사람이 거기서 멈춘다 | `glossary` 등록 + 인라인 툴팁 |

### 제로 베이스라인 — 막대는 필수, 선은 예외

눈은 **막대의 끝점**을 비교한다. 그래서 기준선을 자르면 길이 비교 자체가 거짓이 된다.

> 실제 사례: 세율 35% → 39.6%를 y축 34부터 그린 방송 그래프.
> 막대 높이는 1과 5.6이 되어 **시각적 증가 460%**. 0에서 그리면 **실제 13%**다.

선그래프는 다르다. **공간상 상대 위치**를 보므로 비영점 기준선을 써도 된다.
다만 비영점임을 명시하고, 미세한 차이를 크게 보이도록 과잉 확대하지 않는다.

**축을 조작해 주장을 강화하는 것은 하지 않는다.** 한 사람만 알아채도 주장 전체가 버려진다.

### 계열 수 상한 — 4개

사람의 단기기억은 한 번에 **약 4덩어리**만 유지한다.
계열이 10개인데 색이 10가지고 범례가 옆에 있으면, 독자는 범례와 데이터를 왕복하느라
정작 내용을 처리할 여력이 없다.

- 선·누적: **4개(최대 5개)**. 넘으면 §8의 3전략
- 넘는 계열은 "기타"로 묶고 `group_detail`에 원자료를 넣는다

## 3. 차트별 세부 규칙

### 단순 텍스트 (simple_text)

전할 숫자가 한두 개면 **숫자 자체를 크게** 쓴다.
값 두 개를 막대 차트로 그리면 숫자가 힘을 잃고, 라벨 위치에 따라 비율까지 오독된다.

- 숫자를 가장 크게, 그 뒤에 짧은 설명 문장
- 여러 수치를 하나(예: 변화율)로 줄일 때는 **잃는 맥락**을 따져본다.
  "50% 감소"보다 "41% → 20%"가 크기 감각을 남긴다

### 막대 (bar / bar_sorted)

- **y축 0 시작 필수.**
- **가로막대가 범주형의 기본 선택**이다. 범주명이 길어도 읽히고, z자 스캔에서 **범주명을
  데이터보다 먼저** 만나므로 데이터에 닿을 때 이미 무엇인지 안다.
  (세로막대는 데이터와 범주명 사이를 눈이 왕복한다)
- `ranking`이면 반드시 정렬. 정렬 없는 순위 차트는 순위 차트가 아니다.
- 항목 8개 초과 → 가로 막대로. **라벨이 기울어지면 이미 실패다.**
- 항목 12개 초과 → 상위 N + "기타". 기타에 무엇이 묶였는지 각주에 쓴다.
- **막대 폭 > 막대 사이 간격.** 단, 너무 두꺼우면 길이가 아니라 면적을 비교하게 된다.

**범주 정렬 논리**
- 자연 순서가 있으면 따른다 (연령대 0–10, 11–20 … / 학교급 초·중·고 / 리커트 척도)
- 없으면: 가장 큰 것이 중요하면 위에 두고 내림차순. 가장 작은 것이 중요하면 반대.
- **정렬은 독자에게 해석의 틀을 주는 것이다.** 가나다순은 대부분 패턴을 지운다.

### 축 라벨 vs 직접 라벨 — 둘 중 하나만

| 무엇이 중요한가 | 처리 |
|---|---|
| **큰 추세** | 축을 남기되 **회색으로 죽인다**. 데이터 라벨은 붙이지 않는다 |
| **구체적 수치** | 데이터에 **직접 라벨**하고 **축은 지운다**(중복) |

둘 다 넣지 않는다. 독자가 화면을 어떻게 쓰기를 원하는지 정하고 거기에 맞춘다.

### 선 (line)

- **연속형 데이터**에만 쓴다. 점이 선으로 이어지면 연결을 암시하므로 범주형에는 부적합.
- 계열 4개 이하. 그 이상이면 §8의 3전략.
- **범례 대신 선 끝에 계열명을 직접** 쓴다. 라벨 색은 선 색과 같게.
- 데이터가 없는 구간은 0으로 잇지 않는다. 선을 끊고 각주에 쓴다.
- 추이 차트에는 목표선·전년 동기선 같은 **비교 기준선**을 넣는다. 추이만으로는 좋은지 나쁜지 모른다.
  기준선은 **얇은 회색**으로 배경에 둔다.
- **x축 간격은 실제 시간 간격에 비례해야 한다.** 10년 단위와 1년 단위를 같은 폭으로 놓으면 오도한다.
- **예측치는 실적과 시각적으로 구분한다** — 실적은 실선, 예측은 **얇은 점선**(불확실성의 함의),
  예측 구간에 옅은 배경 음영, 축 아래 `실적 | 예측` 라벨.

### 슬로프그래프 (slopegraph)

**두 시점 또는 두 비교점** 사이에서 여러 범주의 상대적 증감을 한 번에 보여준다.
절대값(양 끝 점)과 변화율(기울기)을 동시에 준다. "변화율"이라는 말을 설명할 필요가 없다.

- 왼쪽·오른쪽 양끝에 **범주명 + 값**을 직접 쓴다. 범례를 쓰지 않는다
- 선이 많이 겹치면 부적합하다. 이때는 **한 계열만 강조**하고 나머지를 회색으로 죽인다
- 범주 순서를 통제해야 하면 슬로프그래프가 아니라 **막대나 100% 누적 막대**를 쓴다
  (슬로프그래프의 세로 위치는 값이 정한다)
- 부분–전체 개념이 필요하면 이것으로는 안 된다

### 누적 막대 / 영역 (stacked_*)

- 계열 4~5개 이하. 순서를 고정한다.
- **축에 붙은 첫 계열만 공통 기준선을 갖는다.** 그 위 계열들은 비교가 어렵다.
  → **가장 중요한 계열을 x축(또는 좌측)에 붙인다.**
- 총계 추이와 구성 비중을 동시에 봐야 하면 차트를 두 개로 나누거나 `views`로 분리한다.
- `stacked_bar_100`은 총량 정보가 사라진다. **총량을 각주에라도 표기한다.**
- **100% 누적 가로막대**는 좌우 양끝에 기준선이 생겨, 리커트 척도(매우 불만~매우 만족)처럼
  **양 극단을 비교해야 할 때** 특히 좋다.
- 여러 열의 같은 세그먼트를 비교시키려면 **경계를 점선으로 연결**한다 (게슈탈트 연결 원칙).
- 범례 대신 **첫 막대의 세그먼트에 이름을 직접** 쓴다.

### 산점도 (scatter)

- 축 라벨에 단위 필수.
- 추세선은 상관을 주장할 때만. 넣으면 R² 또는 표본 수를 각주에.
- 점이 겹치면 투명도나 지터를 준다.

### 발산 막대 (diverging_bar)

- 0 기준선을 굵게. 좌우 스케일을 같게.
- 증가가 나쁜 지표는 색을 반대로 쓴다.

### KPI

- 값 + 라벨 + 비교값(전기·목표) 세 가지. 비교값 없는 KPI는 의미가 약하다.
- 한 줄에 4개까지.
- 증감 방향색은 지표의 좋고 나쁨에 맞춘다.

### 표 (table)

표는 **언어 체계**와 상호작용한다 — 읽는다. 그래프는 **시각 체계**와 상호작용한다 — 본다.
시각이 더 빠르다. 그래서 표는 아래 경우에만 쓴다.

- 여러 청중이 **각자 자기 행**을 찾아야 할 때
- **단위가 여러 개**여서 한 그래프에 담기 어려울 때
- 정확한 숫자 자체가 목적일 때

규칙:
- **테두리를 배경으로 민다.** 회색으로 하거나 아예 없앤다. 도드라져야 할 것은 데이터다
- 수치는 우측 정렬, tabular-nums, 천단위 구분
- 강조할 행만 배경색. 얼룩말 줄무늬는 쓰지 않는다
- 20행을 넘으면 정렬 기준을 명시하고 상위만 보여준 뒤 전체는 `group_detail`로
- 추이·비교를 표로 보여주지 않는다
- **행 방향으로 읽히게 하려면** 셀 간격이나 행 배경색을 쓴다 (근접·유사 원칙).
  세로 구분선을 긋지 않는다

### 마리메코 (marimekko)

두 축으로 동시에 쪼갠다. **가로폭 = 그 열의 크기, 세로 분할 = 그 안의 구성.**
"어느 채널이 큰가"와 "그 채널 안에서 무엇이 팔리나"를 한 화면에서 답한다.

- 열 5개 이하, 계열 6개 이하. 넘으면 읽히지 않는다
- **가로폭이 값을 가진다는 것을 명시한다.** 축 라벨에 "폭 = 매출"이라고 쓴다
- 각 칸에 라벨을 넣을 공간이 없으면 툴팁으로 보낸다. 억지로 넣어 겹치지 않는다
- 열 라벨 아래에 그 열의 절대값을 적는다. 비중만 있으면 크기 정보가 사라진다
- 셀 테두리는 흰색 0.8px. 칸 경계가 안 보이면 마리메코가 아니라 색면이다

누적 100% 막대와 다르다. 누적 100%는 열 폭이 모두 같아 **크기 차이가 지워진다.**
크기와 구성을 동시에 봐야 하면 마리메코를 쓴다.

### 워터폴 (waterfall)

A에서 B로 가는 동안 무엇이 더하고 뺐는지 보여준다. 증감 분해의 기본형이다.

- 시작·끝 합계 막대는 **중립색**(`--g2`), 증감만 방향색(`--up`/`--dn`)
- 각 막대는 앞 막대의 끝에서 시작한다. 연결선을 얇게 긋는다
- 항목 8개 이하. 그 이상이면 작은 것을 "기타"로 묶고 `group_detail`을 채운다
- 값 라벨에 부호를 붙인다 (`+12.4`, `−3.2`)
- 시작값과 끝값을 축 라벨에 명시한다. 증감 합이 차이와 맞는지 검산한다

"왜 늘었나/줄었나"라는 질문에는 막대 두 개가 아니라 워터폴이 답이다.

### 코로플레스 지도 (choropleth)

지역 데이터의 기본형이다. 자세한 구현은 `references/korea-map.md`.

- **지역명 막대 차트만 쓰지 않는다.** 순위는 보이지만 분포가 안 보인다
- 지도 단독으로 쓰지 않는다. **지도 + 정렬된 표**를 나란히 두고 서로 연동한다
  지도는 분포를, 표는 정확한 값을 담당한다
- 색 계조는 5~7단계. 연속 색상환을 쓰지 않는다
- 범례에 `낮음 ─ 높음`과 양 끝 값을 표기한다
- 면적이 큰 지역이 값도 커 보이는 착시가 있다. 표를 반드시 함께 둔다
- 시군구 단위는 개수가 많아 지도만으로는 못 읽는다. 상위 N개 표를 같이 낸다

### 히트맵 (heatmap)

`composition_2d`에서 마리메코가 안 맞을 때(값이 비중이 아니라 밀도일 때) 쓴다.

- 단색 계조. 한 색상 안에서만 진하기를 바꾼다
- 셀에 값을 직접 쓴다. 색만으로 수치를 읽게 하지 않는다
- 행·열을 값 순으로 정렬한다. 가나다순은 패턴을 지운다


## 4. 라벨과 단위

- 축 라벨에 단위를 쓴다: `출고량 (부)`, `매출 (백만원)`.
- 큰 수는 축 라벨에서 단위를 접는다: 12,400,000원 → 축 `매출 (백만원)`, 값 `12.4`.
- 퍼센트와 퍼센트포인트를 구분한다. 증감은 대부분 %p다.
- 기간 라벨은 데이터 기준으로 정확히: `2026-08` (O), `8월` (기간이 모호하면 X).

## 5. 항목을 묶을 때

항목이 많으면 묶어야 읽힌다. 묶는 것 자체는 옳다. **묶고 나서 열어볼 수 없게 두는 것이 문제다.**

| 차트 | 묶는 기준 |
|---|---|
| 막대·순위 | 상위 10~12개 + 기타 |
| 누적·마리메코 | 계열 5~6개 + 기타 |
| 워터폴 | 8개 + 기타 |
| 파이 | (쓰지 않는다) |

묶었으면 반드시

1. 스펙의 `group_detail`에 **묶기 전 원자료 전체**를 넣는다
2. 화면에서 그 항목을 클릭할 수 있게 한다 (`i` 아이콘 또는 클릭 행)
3. 모달 상단에 합계와 전체 대비 비중을 적는다
4. 각주에도 무엇이 묶였는지 한 줄로 적는다 — 모달을 못 여는 환경(인쇄·문서 변환)을 위해

`group_detail`이 비어 있으면 렌더링하지 않고 스펙을 되돌려 보낸다.

### 본문 표는 근거지 원자료가 아니다

**전체 값을 담은 정렬 가능한 표를 본문에 두지 않는다.** 정렬 버튼이 있다는 것은
"필요한 걸 알아서 찾으세요"라는 뜻이고, 그건 결론을 전달하지 않겠다는 말이다.

| | 본문 표 | 모달·드릴다운 |
|---|---|---|
| 행 수 | **12행 이하** | 제한 없음 |
| 목적 | `action_title`을 뒷받침하는 숫자를 정확히 보이기 | 원자료 전량 |
| 열 | 주장에 필요한 것만 | 전부 |
| 정렬 | 고정. 주장에 맞는 순서 하나 | 자유 |

- 13행 이상이면 차트로 바꾸거나, 상위 N + 기타로 묶고 전량은 모달로 내린다
- 본문 표에서 **글자가 잘리면 안 된다.** 잘릴 열이면 그 열이 본문에 있을 이유가 없다
- `question_type: detail`(정확한 숫자를 봐야 함)일 때만 표가 주인공이 된다.
  그 경우에도 12행을 넘기면 위와 같다

## 6. 축약어와 산식

차트 라벨·축 라벨·각주에 나오는 말도 본문과 같은 규칙을 적용한다.

- 축약어(GMV, SKU, DOS…)와 사내 용어(초도배본, 순출고, 수불…)는 `glossary`에 등록한다
- 처음 나오는 자리에 점선 밑줄 + 호버 툴팁
- 산식이 한 문장으로 안 되면 `i` 아이콘 → 모달
- 축 라벨 자체를 축약하지 않는다. `GMV(백만원)`이 `GMV`보다 낫다

## 7. 한 차트에 한 가지만

차트가 복잡해서가 아니라 **제목이 여러 주장을 담아서** 읽기 어려워지는 경우가 더 많다.

- `action_title`은 주장 하나. `—`로 두 주장을 잇지 않는다
- 부가 수치는 `so_what`이나 각주로 내린다
- 한 차트에서 두 가지를 말해야 하면 **exhibit을 쪼갠다**

다만 아래는 쪼개는 게 아니라 묶는다.

| 상황 | 처리 |
|---|---|
| 같은 질문을 다른 축으로 봐야 한다 (지역별 ↔ 학교급별) | `views` 토글 |
| 묶은 단위에서 개별 단위로 내려가야 한다 (지역 유형 → 시군구) | `drilldown` |
| 축을 바꾸면 결론이 뒤집힌다 | **별도 exhibit.** 그건 다른 질문이다 |

### 계층이 있으면 위에서 시작한다

수백 개의 개별 단위를 처음부터 보여주지 않는다.
**묶어서 패턴을 보이고, 궁금한 그룹만 열게 한다.**

- 상위 단계는 3~5개 그룹. 이 수를 넘으면 패턴이 안 보인다
- 그룹은 데이터에 없어도 만들 수 있다. 단 **분류 근거를 반드시 적고, 그 근거는 결과 변수와
  독립이어야 한다** — 결과로 나눈 그룹이 결과에서 다르다는 것은 아무것도 밝히지 않는다
- 2단계까지만. 3단계 이상은 대시보드가 아니라 데이터 탐색 도구다

## 8. 선이 얽힐 때 — 스파게티 대응 3전략

계열이 많아 선이 서로를 가리는 그래프는 정보가 없는 그래프다.
차트 종류를 바꾸기 전에 **먼저 물어야 할 것: 모든 계열이 필요한가? 모든 기간이 필요한가?**
**데이터를 줄이는 것도 해법이다.**

| 전략 | 방법 | 언제 |
|---|---|---|
| **① 하나씩 강조** | 한 선만 색·굵기·마커로 살리고 나머지는 `--g4` 회색 | 계열마다 할 말이 있고 `emphasis_steps`로 순회할 때 |
| **② 세로 분리** | 계열마다 작은 그래프를 세로로 쌓고 **x축을 공유**. y축은 감추되 **min/max를 모두 동일**하게 | 계열별 추세가 계열 간 비교보다 중요할 때 |
| **③ 가로 분리** | 계열마다 작은 그래프를 가로로 놓고 **y축을 공유** | 계열 간 값 크기 비교가 중요할 때 |
| **④ 결합 = small multiples** | ②·③처럼 분리하되 각 패널에서 해당 계열만 강조하고 나머지는 배경에 남긴다 | 전체 맥락이 필요하면서 하나씩 봐야 할 때. **배포 문서에 적합** |

**②·③·④에서 축의 min/max가 패널마다 다르면 비교가 거짓이 된다.** 반드시 고정한다.
각 패널에는 시작값·끝값만 라벨하고 축 눈금은 지운다.

## 9. 같은 데이터를 다시 보여줄 때 — 순서를 바꾸지 않는다

한 데이터셋으로 여러 이야기를 해야 할 때가 있다. 이야기마다 정렬을 최적화하고 싶어진다.
**하지 말 것.**

> 독자를 데이터에 익숙해지게 만들어 놓고 완전히 재배열하는 것은 **불필요한 인지 세금**이다.

올바른 방법:

1. **기본 시각물(base visual)**을 하나 만든다. 여기서 순서·축·색 체계를 확정한다
2. 그 다음부터는 **강조만 옮긴다** (`emphasis_steps`). 순서·축·라벨은 건드리지 않는다
3. 강조 대상이 공통 기준선에 정렬돼 있지 않아 순위가 안 읽히면,
   순서를 바꾸는 대신 **굵은 색 + 콜아웃 박스**로 보완한다
4. 배포용에서는 이 단계들을 **하나의 종합 화면**으로 압축할 수 있다.
   단 강조 색을 단계별로 다르게 하고, 각 색에 대응하는 설명 박스를 옆에 붙인다

**`views`와 `emphasis_steps`는 다르다.**

| | 바뀌는 것 | 예 |
|---|---|---|
| `views` | **축이나 단위가 바뀐다** | 구성비(%) ↔ 절대 부수 / 지역별 ↔ 학교급별 |
| `emphasis_steps` | **데이터·순서·축이 전부 같고 강조만 이동** | 같은 100% 누적 막대에서 ①중학 강조 → ②고등 강조 |

축을 바꾸면 결론이 뒤집히는 경우는 둘 다 아니다. **별도 exhibit**이다.
