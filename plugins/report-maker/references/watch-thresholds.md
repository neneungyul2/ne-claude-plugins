# 감시형 임계값 (watch-thresholds)

`report_type: watch`는 **임계값이 없으면 성립하지 않는다.** 임계값이 없으면
매번 사람이 숫자를 보고 "이게 이상한가"를 판정해야 하고, 그러면 자동화된 게 없다.

여기는 **임계값을 어떻게 정하고 어떻게 쓰는가**다.
감시형이 무엇인지는 `report-types.md`를 본다.

---

## 1. 임계값은 플러그인이 아니라 사용자 작업 폴더에 둔다

자주 바뀐다. 조직마다 다르다. 플러그인에 박으면 전부가 같은 기준을 쓰게 된다.

작업 폴더의 `.report-watch-rules.json`을 읽는다. 없으면 **골격을 만들어 보여주고
어떤 룰부터 수치를 정할지 묻는다.** 임의로 채우지 않는다.

```
{
  basis  unit
  rules [{ id  label  metric  condition  threshold  severity }]
}
```

| 필드 | 내용 |
|---|---|
| `basis` | 어느 기준의 숫자인가. 기준이 다르면 임계값도 다르다 |
| `id` | 결론문에 표시할 식별자 |
| `label` | 사람이 읽을 이름 |
| `metric` | 무엇을 재나 |
| `condition` | 아래 2장 |
| `threshold` | 수치. **합의 전에는 `null`** |
| `severity` | `high` \| `mid` \| `low`. 결론문 정렬 순서 |

**룰이 몇 개인지는 이 조각이 정하지 않는다.** 그 화면이 무엇을 지켜보는지가 정한다.

---

## 2. 조건 어휘 — 무엇과 비교해 이상하다고 하는가

| 갈래 | 비교 대상 | 언제 쓰나 |
|---|---|---|
| **절대 기준** | 고정된 수치 | 넘으면 안 되는 선이 이미 있다 (재고 일수, 결품률) |
| **직전 대비** | 바로 앞 기간 | 급변을 잡는다. 계절성이 있으면 오탐이 많다 |
| **이동평균 대비** | 최근 N기간 평균 | 계절성·요일 효과를 흡수한다. 기본으로 쓸 만하다 |
| **목표 대비** | 계획·목표 | 목표가 실제로 있을 때만. 없으면 이건 추적형이다 |
| **분포 이탈** | 과거 분포의 상·하위 % | 기준을 못 정하겠을 때 데이터가 정하게 한다 |
| **기여도** | 전체 변화 중 한 항목의 몫 | "전체가 줄었는데 사실 한 곳 때문"을 잡는다 |

**직전 대비만으로 감시를 짜지 않는다.** 월요일마다 걸리고 연휴마다 걸린다.
계절성·요일 효과가 있는 지표는 이동평균 대비나 분포 이탈로 간다.

---

## 3. 처음 임계값을 정할 때

수치를 감으로 정하면 둘 중 하나가 된다 — 매번 걸리거나, 한 번도 안 걸리거나.
둘 다 **아무도 안 보게 되는 결과**는 같다.

### ① 걸리는 빈도에서 역산한다

**"이 화면이 얼마나 자주 나를 불러야 하는가"를 먼저 정하고, 거기에 맞춰 수치를 뽑는다.**

주 1~2회가 대체로 적당하다. 매일 걸리면 사람이 무시하기 시작하고,
한 달에 한 번도 안 걸리면 화면을 안 열게 된다.

과거 데이터에 그 룰을 돌려보고 몇 번 걸리는지 센다. 목표 빈도가 나올 때까지 수치를 옮긴다.

### ② 실제로 문제였던 사건이 걸리는지 본다

과거에 대응이 필요했던 날을 두세 개 꼽고, **그 날이 걸리는지** 확인한다.
안 걸리면 임계값이 둔한 것이다. 이게 빈도보다 중요하다 —
빈도만 맞추면 엉뚱한 것이 알맞은 횟수로 걸린다.

### ③ 못 정하면 비워둔다

합의가 안 됐거나 과거 데이터가 부족하면 `threshold`를 `null`로 둔다.

- `null`인 룰은 **평가하지 않는다**
- 산출물의 "확인 필요"에 `임계값 미설정`으로 표시한다
- **추정값을 넣고 조용히 돌리지 않는다.** 틀린 판정이 나가고, 틀렸다는 걸 아무도 모른다

---

## 4. 결론문 — 걸린 룰 하나에 문장 하나

서술형으로 쓴다. 룰 이름만 나열하지 않는다.

- **수치를 반드시 넣는다.** "많이 줄었다"는 결론이 아니다.
  무엇이 얼마에서 얼마로 갔는지, 기준 대비 몇 %p인지 적는다
- `severity` 순으로 정렬한다
- 5개를 넘으면 상위 5개만 상단에 올리고 나머지는 표로 내린다
- **원인을 지어내지 않는다.** "비수기 영향으로 보인다"는 데이터가 뒷받침하지 않으면 쓰지 않는다.
  원인을 밝혀야 하면 그건 감시형이 아니라 **별도의 진단 리포트**다

### 아무것도 안 걸렸을 때

**"특이사항 없음"은 정상 출력이다.** 실패가 아니다. 다만 그것만 쓰면 안 된다.

**무엇을 확인했는지 함께 적는다.** "특이사항 없음"만 있으면
돌린 것과 안 돌린 것이 구분되지 않는다. 임계값 미설정 룰도 여기서 함께 밝힌다.

---

## 5. 구성을 매번 바꾸지 않는다

감시형은 **exhibit이 고정 슬롯**이다. 이번에 흥미로운 것이 생겼다고 섹션을 추가하면
독자가 매번 화면을 새로 익혀야 한다.

흥미로운 것이 생겼으면 그건 **별도의 진단 리포트**다. 감시 화면은 그대로 둔다.

룰 자체를 바꿀 때도 마찬가지다 — 바꾼 날과 무엇을 바꿨는지 각주에 남긴다.
임계값이 조용히 바뀌면 과거 결과와 비교할 수 없게 된다.
