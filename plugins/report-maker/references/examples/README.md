# 예시 — 읽는 법

여기 있는 파일은 **스키마가 실제로 어떻게 생겼는지 한 번 확인하는 용도**다.
지침이 아니다. 지침은 `skills/*/SKILL.md`와 `references/*.md`에 있다.

## 이 폴더를 여는 경우

- 스키마 문서의 필드 설명만으로 중첩 구조가 잡히지 않을 때
- 렌더러가 스펙을 못 읽어서, 형식이 맞는 스펙과 대조해봐야 할 때

**그 외에는 열지 않는다.** 스펙을 새로 쓸 때 여기부터 보면, 지침이 아니라 예시를 따라가게 된다.

## 예시에서 가져오면 안 되는 것

| | 왜 |
|---|---|
| **exhibit 개수** | `brief.questions`가 정한다. 예시에 하나 있다고 하나만 만들지 않는다 |
| **exhibit 순서** | 결론 → 근거 → 세부의 cascading이 정한다 |
| **차트 종류** | 각 view의 `question_type`이 정한다 (`references/chart-rules.md`) |
| **섹션 구성·흐름** | 답할 질문이 정한다. 예시의 흐름은 그 예시의 질문에서 나온 것이다 |
| **값·제목·용어·기준** | 전부 자리표시자다 |
| **키 목록** | 필수 여부는 스키마 문서의 표가 정한다. 예시에 없는 키가 선택 필드인 것은 아니다 |

## 가져와도 되는 것

- 키의 **중첩 위치** (`views`가 `exhibits[]` 안에 있다는 것 같은)
- 값의 **자료형** (`rows`가 배열의 배열이라는 것 같은)

## 파일

| 파일 | 무엇 |
|---|---|
| `quick-minimal.json` | quick 모드에서 필수 필드만 채운 스펙 한 벌 |
