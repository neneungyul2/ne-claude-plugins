# 디자인 규칙 (design-rules)

quick·report, HTML·문서 어디에나 동일하게 적용한다.

---

## 1. 배치 — 결론이 먼저다

시선은 좌상단에서 시작해 오른쪽으로, 다시 아래로 내려간다(F 패턴).
동시에 보고 문서는 결론 → 근거 → 세부의 피라미드 구조를 갖는다. 이 둘이 같은 방향을 가리킨다.

```
좌상단  헤드라인 (서술형 결론, 화면에서 가장 큰 글자)
  ↓     요약 3줄
  ↓     exhibit 1 — 헤드라인을 가장 직접 뒷받침하는 것
  ↓     exhibit 2, 3 ...
아래    각주 · 확인 필요 항목
```

- 헤드라인보다 큰 요소를 만들지 않는다. 로고·제목·장식이 결론보다 크면 안 된다.
- exhibit 순서는 중요도 순이다. 데이터 순서나 엑셀 컬럼 순서가 아니다.
- 상단 우측에는 **기준 배지**만 둔다 (`기준: 순출고 · 2026-08 · 단위 부`).

---

## 2. 데이터-잉크 비율

숫자를 전달하지 않는 픽셀은 지운다.

지울 것

- 가로 격자선 (꼭 필요하면 아주 연하게 1~3개)
- 세로 격자선
- 차트 테두리, 배경 박스, 그림자, 그라데이션
- 범례 — 가능하면 계열명을 선·막대 옆에 직접 쓴다
- 축 눈금 표시(tick mark)
- 소수점 — 부·건·원 단위에서 소수점은 거의 항상 불필요

남길 것

- 축 라벨과 단위
- 값 라벨 (항목이 8개 이하면 막대 위에 직접)
- 기준선·목표선

---

## 3. 색

색은 **의미가 있을 때만** 쓴다. 예쁘게 하려고 쓰지 않는다.

| 용도 | 규칙 |
|---|---|
| 방향 | 증가 초록 / 감소 빨강. **단, 증가가 나쁜 지표(반품률·재고일수)는 반대로.** 판단해서 쓴다 |
| 상태 | 양호 / 주의 / 위험 3단계. 4단계 이상 만들지 않는다 |
| 강조 | **한 화면에 강조색 1개.** 두 개를 강조하면 강조가 아니다 |
| 계열 구분 | 단색 계조(진한 회색 → 연한 회색). 색상환을 돌지 않는다 |

- 무지개 팔레트, 기본 팔레트 그대로 쓰기 금지.
- 색만으로 정보를 구분하지 않는다. 라벨·위치·패턴을 함께 쓴다.
- 대비: 본문 텍스트는 배경 대비 4.5:1 이상.
- 라이트·다크 모두에서 읽히게 한다. 색을 CSS 변수로만 정의한다.

---

## 4. 타이포그래피

- 폰트는 시스템 기본. 웹폰트를 불러오지 않는다.
- 위계는 **3단계까지**: 헤드라인 / exhibit 제목 / 본문. 그 이하는 색으로 구분한다.
- 수치는 tabular-nums. 자릿수가 흔들리면 비교가 안 된다.
- 천단위 구분 기호를 넣는다. 단위는 축이나 각주에 한 번만.
- 한 줄 길이는 34em 이하.

---

## 5. 여백

- 섹션 간격 > 요소 간격 > 요소 내부 간격. 이 순서가 뒤집히면 묶음이 잘못 읽힌다.
- exhibit 사이는 구분선 1개 + 넉넉한 상단 여백. 박스로 감싸지 않는다.
- 모바일 폭에서도 좌우 여백 16px 이상을 유지한다.

---

## 6. 각주

모든 exhibit에 **출처 · 기간 · 단위 · 집계기준** 4요소. 본문보다 작게, 회색으로.

- 각주는 exhibit 바로 아래. 문서 끝으로 몰지 않는다.
- 데이터 한계(누락·추정·제외 항목)가 있으면 각주에 쓴다. 숨기지 않는다.

---

## 7. 인터랙션 (HTML만)

인터랙션은 **마지막에** 붙인다. 없어도 성립하는 화면을 먼저 만든다.

- 툴팁: 기본. 값·라벨·단위.
- 필터: "이 화면을 보고 바로 이어서 나올 질문"에만. 기간·채널 정도가 한계다.
  필터를 걸면 현재 상태를 글자로 표시한다. 필터 걸린 화면을 캡처해 공유해도 오해가 없어야 한다.
- 드릴다운·정렬 토글·다운로드는 요청이 있을 때만.

---

## 8. 하지 않는 것

- 제목에 "현황", "분석", "추이" 같은 명사구만 쓰기 → 서술형 결론으로
- 데이터가 없는 구간을 0으로 그리기 → 끊어서 표시하고 각주에 명시
- 축을 잘라 차이를 부풀리기
- 한 화면에 서로 다른 집계 기준을 말없이 섞기
- 애니메이션으로 주의를 끌기
