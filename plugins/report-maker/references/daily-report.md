# 영업일보 (daily-report)

일보는 일반 대시보드와 성격이 다르다.

- 수신자가 대표부터 파트원까지 **다층**이다
- 매일 반복되고 질문이 고정되어 있다 — "어제 무슨 일이 있었고 오늘 뭘 해야 하나"
- 따라서 **브리프 단계를 매번 돌리지 않는다**

핵심 기능은 **임계값 기반 결론문 자동 생성**이다.

---

## 1. 절차

1. 임계값 설정 파일을 읽는다 (3장). 없으면 만들고 시작한다.
2. 데이터를 불러온다 (`load-data`). 기준은 설정 파일에 고정되어 있다.
3. **룰을 하나씩 평가한다.** 걸린 룰만 모은다.
4. 걸린 룰을 심각도 순으로 정렬해 **상단 결론**으로 올린다.
5. **아무것도 걸리지 않으면 "특이사항 없음"을 명시적으로 쓴다.** 억지로 결론을 만들지 않는다.
6. 고정 exhibit(2장)을 붙인다.
7. 렌더링한다 (기본 HTML).

브리프(수신자·의사결정·핵심 메시지)는 묻지 않는다. 일보는 이미 정해져 있다.

---

## 2. 고정 구성

| 위치 | 내용 |
|---|---|
| 상단 | 날짜 · 기준 배지 |
| 결론 | 걸린 룰 → 서술형 문장. 없으면 "특이사항 없음" |
| ex1 | 어제 실적 KPI (출고·반품·목표 대비) |
| ex2 | 최근 30일 추이 (목표선 포함) |
| ex3 | 채널별 전일 대비 |
| ex4 | 주의가 필요한 종/채널 (룰에 걸린 항목만. 없으면 이 exhibit 생략) |
| 하단 | 각주 4요소 · 확인 필요 항목 |

exhibit 4는 **조건부**다. 걸린 게 없으면 빈 표를 넣지 말고 아예 뺀다.

---

## 3. 임계값 설정

임계값은 자주 바뀌므로 **플러그인이 아니라 사용자 작업 폴더**에 둔다.

`.report-daily-rules.json`

```json
{
  "basis": "순출고",
  "unit": "부",
  "rules": [
    {
      "id": "dod_deviation",
      "label": "전일 대비 이탈",
      "metric": "출고량",
      "condition": "abs_pct_change_vs_prev_day",
      "threshold": null,
      "severity": "high"
    },
    {
      "id": "target_shortfall",
      "label": "목표 대비 미달",
      "metric": "출고량",
      "condition": "pct_of_target_below",
      "threshold": null,
      "severity": "high"
    },
    {
      "id": "single_channel_swing",
      "label": "특정 채널 단독 변동",
      "metric": "채널별 출고량",
      "condition": "single_channel_explains_total_change_above",
      "threshold": null,
      "severity": "mid"
    },
    {
      "id": "return_spike",
      "label": "반품 급증",
      "metric": "반품",
      "condition": "abs_pct_change_vs_trailing_avg",
      "threshold": null,
      "severity": "mid"
    },
    {
      "id": "stockout_risk",
      "label": "품절 위험",
      "metric": "재고",
      "condition": "days_of_supply_below",
      "threshold": null,
      "severity": "high"
    }
  ]
}
```

> **임계값 수치는 미정이다. `threshold`가 `null`인 룰은 평가하지 않고,
> 산출물의 "확인 필요"에 "임계값 미설정" 으로 표시한다.**
> 추정값을 넣고 조용히 돌리지 않는다. — TODO: 실무 합의 후 수치 확정

설정 파일이 없으면 위 골격을 만들어 사용자에게 보여주고, 어떤 룰부터 수치를 정할지 묻는다.

---

## 4. 결론문 작성

걸린 룰 하나 = 결론 문장 하나. 서술형으로 쓴다.

```
[dod_deviation]  A채널 출고가 전일 대비 34% 감소했다 (12,400 → 8,180부)
[target_shortfall]  8월 누계가 월 목표의 71% 수준으로, 기간 진행률(90%)에 19%p 미달이다
```

- 수치를 반드시 넣는다. "많이 줄었다"는 결론이 아니다.
- 심각도 high → mid 순으로 정렬한다.
- 5개를 넘으면 상위 5개만 올리고 나머지는 exhibit 4의 표로 내린다.
- **원인을 지어내지 않는다.** "여름 비수기 영향으로 보인다" 같은 문장은 데이터가 뒷받침하지 않으면 쓰지 않는다.

### 특이사항이 없을 때

```
특이사항 없음 — 전일 대비 변동, 목표 대비 진행률, 반품 모두 임계값 이내
```

무엇을 확인했는지 함께 쓴다. "특이사항 없음"만 쓰면 안 돌린 것과 구분이 안 된다.

---

## 5. 파일럿 운영

일보는 매일 돌아가므로 피드백이 하루 단위로 들어온다. 1호 검증 대상으로 삼는다.

- 오탐(걸리면 안 되는데 걸린 것)과 미탐(걸려야 하는데 안 걸린 것)을 기록한다.
- 2주 정도 모아서 임계값을 조정한다. 하루 단위로 바꾸지 않는다.
- 조정 이력을 설정 파일 옆에 남긴다.
