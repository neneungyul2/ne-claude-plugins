# 문장과 단락 연결 (writing-rules)

**plan-report가 스펙 문장을 쓸 때, build-html이 화면에 옮길 때, verify-report가 검수할 때 읽는다.**
데이터와 구성이 맞아도 문장이 읽히지 않으면 보고서는 실패한다.

---

## 1. 단락의 머리 — 제목과 결론 문장을 나눈다

한 단락(exhibit)의 머리는 두 줄이다.

| 자리 | 스펙 필드 | 쓰는 법 | 길이 |
|---|---|---|---|
| 제목 | `title` | **짧은 명사구.** 이 단락이 무엇을 보는지 | 20자 이내 |
| 결론 문장 | `action_title` | 제목 바로 아래 첫 문장. **이 단락의 답 하나** | 60자 이내 |

제목에 결론을 다 넣으면 제목마다 긴 단정문이 붙는다. 화면이 빽빽해지고 무엇을 보는 단락인지가 오히려 흐려진다.
제목은 찾기 위한 것이고, 결론은 첫 문장이 말한다.

| 제목 | 결론 문장 |
|---|---|
| 영역별 광고비와 클릭 | 광고비의 60%를 쓴 영역이 클릭은 9%만 냈다 |
| 지역별 판매 | 판매의 절반은 수도권 밖에서 나왔다 |

위 값은 형태 예시다. 실제 문장은 데이터에서 나온 말로 쓴다.

히어로의 요약 목록은 **결론 문장**을 순서대로 모은 것이다. 제목이 아니다.

---

## 2. 단락 사이 — 질문이 이어져야 한다

각 단락은 **앞 단락을 읽은 독자가 품게 되는 질문**에 답한다. 스펙에 `reader_question`으로 적는다.

```
결론        "추가 집행을 보류하자"
  → 무엇을 샀나?         대상 설명
  → 얼마를 썼나?         범위·전체 현황 (원래 값)
  → 값어치를 했나?       전체 효율 (비율 지표, 전체 평균)
  → 어디가 특히 나쁜가?   부분 비교
  → 왜 나쁜가?           원인
  → 다른 이유는 아닌가?   다른 설명 점검
  → 무엇이 남았나?       한계 · 다음 할 일 → 다시 요청으로
```

질문만 이어 읽어도 이야기가 되어야 한다. 질문이 앞 단락의 결론에서 나오지 않으면 순서가 틀렸거나 단락이 빠진 것이다.

**앞 단락을 받는 말(`bridge`)** — 필요하면 결론 문장 앞에 짧은 구를 붙인다.
"앞에서 본 4,390만원 가운데"처럼 **앞의 결과를 가리키는 구**이지, 새 주장이 아니다.
화면에서는 결론 문장과 한 문장으로 이어 보인다.

---

## 3. 문장 규칙

- **한 문장에 정보 하나.** 쉼표로 이어 붙이지 않는다. 본문 한 문장은 80자를 넘기지 않는다
- **쉬운 말 먼저.** 용어는 처음 나올 때 쉬운 말로 풀어 쓴다. 툴팁은 보조이지 대신이 아니다
- **되풀이하지 않는다.** 제목·결론 문장·`so_what`이 같은 말을 세 번 하지 않는다
- **강조만 하는 문장을 쓰지 않는다.** 정보가 없는 문장은 지운다
- **숫자는 비교 대상과 함께.** "9.0만원"만 쓰지 않고 "9.0만원(평균 주문 금액 1.4만원의 6배)"처럼
  무엇과 견주는지를 같은 자리에 둔다
- 본문은 평서문(~다)으로 끝낸다

### 쓰지 않는 말

AI가 쓴 티가 나는 말이다. 뜻을 더하지 않고 문장만 길게 만든다. `check_html.py`가 경고한다.

| 쓰지 않는 말 | 대신 |
|---|---|
| ~라는 구조다 · ~하는 구조다 | 무엇이 어떻게 되는지 그대로 쓴다 |
| 핵심은 ~ · 주목할 점은 ~ | 그 내용을 바로 쓴다 |
| ~을 시사한다 · ~을 보여준다 | 근거가 있으면 "~이다", 없으면 쓰지 않는다 |
| ~할 필요가 있다 | "~한다". 요청이면 요청 자리로 |
| 유의미한 · 의미 있는 (검정 없이) | 숫자로 쓴다 |
| 다양한 · 효과적으로 · 적극적으로 · 전략적으로 | 지운다 |
| ~측면에서 · ~관점에서 | 지운다 |
| 명확히 · 분명히 · 확실히 · 매우 · 크게 | 숫자로 쓴다 |
| 결론적으로 · 요컨대 · 즉, | 지운다 |
| ~인 셈이다 | "~이다" |
| 문장 가운데 줄표(—)로 두 말 잇기 | 두 문장으로 나눈다 |

번역투도 줄인다 — "~에 대한", "~를 통해", "~에 있어서".

---

## 4. 이름표를 화면에 쓰지 않는다

만드는 쪽의 틀(숲·나무·가지, 1막·2막, 가설·검증)은 **생각하는 순서**다. 화면의 이름표가 아니다.
단락 제목과 막대 이름은 **그 데이터의 말**로 쓴다 — "연 광고 예산 → 진행 광고비 → 분석 대상".
"먼저 전체 그림" 같은 안내 문구를 단락 제목으로 쓰지 않는다. 제목은 내용을 말한다.
