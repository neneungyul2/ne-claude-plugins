# Metabase 어댑터

**Metabase는 사내망 전용이다.** 접근이 안 되는 사용자가 반드시 있다.
실패를 예외가 아니라 정상 경로로 취급한다.

---

## 1. 조회 전에

- **DB·스키마·테이블 목록은 런타임에 조회한다.** 이 문서에 적지 않는다.
  적어두면 실제와 어긋나는 순간 해롭고, 갱신할 때마다 플러그인을 재배포해야 한다.
- 먼저 목록을 조회해 대상을 확정하고, 그다음 데이터를 뽑는다.

---

## 2. 알려진 기술적 주의사항

### MSSQL 자동 LIMIT 우회

Metabase가 쿼리 끝에 자동으로 붙이는 제한 때문에 MSSQL에서 의도한 행 수가 안 나올 수 있다.
`TOP n`을 쓰고 쿼리 끝을 주석으로 닫아 자동 삽입을 무력화한다.

```sql
SELECT TOP 10000 ...
FROM ...
WHERE ...
-- 이후 자동 삽입 구문 차단
```

### 타임아웃

큰 조회는 끊긴다. 기간이나 채널로 **분할 조회**한 뒤 합친다.
분할했다면 합친 뒤 행 수와 합계를 대조하고, 분할했다는 사실을 데이터셋 카드에 남긴다.

### 일 스냅샷 테이블

재고처럼 매일 상태를 적재하는 테이블은 **기간 합산 시 중복**된다.
합산 전에 스냅샷인지 이벤트인지 확인한다. 스냅샷이면 기준일 하나를 골라 쓴다.

### 권한

권한은 그룹 단위로 갈린다 (`grp_<db>_<schema>_<permission>`).
연결은 되는데 특정 DB·스키마에서만 거부되면 권한 문제다. 쿼리를 고쳐도 해결되지 않는다.

---

## 3. 실패 시 안내

원인을 구분해서 말한다. "조회에 실패했습니다"로 끝내지 않는다.

| 증상 | 원인 | 안내 |
|---|---|---|
| 서버에 연결 자체가 안 됨 | 사내망 밖 / MCP 미설정 | "Metabase는 사내망에서만 접근됩니다" |
| 연결은 되는데 특정 DB·스키마 거부 | 권한 그룹 | "해당 스키마 조회 권한이 없습니다. 담당자에게 `grp_<db>_<schema>_<권한>` 그룹 추가를 요청하시면 됩니다" |
| 쿼리가 중간에 끊김 | 타임아웃 | 분할 조회 재시도 |
| 결과 행 수가 이상하게 잘림 | 자동 LIMIT | `TOP n` + 주석 종료 재시도 |

그리고 **항상 대체 경로를 같이 제시한다.**

> "결과를 복사해서 붙여넣어 주시거나 엑셀로 내려받아 올려주시면 그대로 진행하겠습니다."

붙여넣기·엑셀로 받으면 해당 어댑터(`paste.md` / `excel.md`)로 계속 진행한다.
Metabase가 안 된다고 작업 전체를 멈추지 않는다.

---

## 4. 정규화

- 조회 결과도 다른 소스와 동일하게 데이터셋 카드를 만든다.
- `추출 시각`에 **쿼리 실행 시각**을 적는다. 카드 캐시를 썼다면 캐시 시점을 적는다.
- 쿼리에 적용한 필터(기간·채널·제외 조건)를 카드의 `주의사항`에 남긴다.
  필터가 곧 집계 기준이다.
- 카드 번호나 쿼리를 각주의 `출처`에 적는다. 나중에 재현할 수 있어야 한다.
