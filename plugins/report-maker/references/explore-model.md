# 탐색형 데이터 모델 (explore-model)

`frame-explore`·`plan-explore`·`build-explore`가 공통으로 참조한다. 보고형의
`metrics.md`(지표 정의)·`report-types.md`(유형별 필수요소)에 대응하는, 탐색형 쪽의
기준 문서다.

---

## 1. 데이터 그레인(grain)

**그레인**은 원자료 한 행이 대표하는 조합의 단위다. "날짜 × 부문 × 채널" 그레인이면
한 행은 특정 날짜의 특정 부문·특정 채널의 값이다.

### 규칙

- 확정된 축(axis) 전체의 조합보다 **같거나 더 세밀해야** 한다. 축이 굵으면 그 축으로
  가른 화면을 만들 수 없다 — 이미 합쳐진 숫자는 다시 나눌 수 없다
- 그레인은 **긴 형식(long format)**으로 남긴다. 축마다 열을 나누는 넓은 형식(wide format)이
  아니라, `(날짜, 부문, 채널, 지표, 값)`처럼 한 행에 한 관측치만 담는 형식이다.
  넓은 형식은 축이 늘어날 때마다 열이 곱으로 늘어나 다루기 어렵다
- **결론에 맞춰 자르지 않는다.** 보고형(`load-data`)은 필요한 값만 추리지만, 탐색형은
  독자가 어떤 조합을 고를지 미리 알 수 없으므로 그레인 전체를 싣는다
- 그레인보다 굵은 파생값(누적, 이동평균, 전년대비)은 **원자료가 아니라 계산 엔진에서**
  런타임에 만든다. 파생값을 미리 계산해 원자료에 섞으면 필터를 바꿀 때마다 다시
  계산해 넣어야 하고, 둘이 어긋나는 버그가 생긴다

### 그레인이 축을 못 받쳐줄 때

- 축을 하나 줄인다 (가장 덜 중요한 축부터)
- 데이터를 더 세밀한 단위로 재요청한다
- 안 되면 그 조합은 `out_of_scope`로 명시하고, 화면에서도 "이 조합은 데이터 단위상
  볼 수 없음"으로 표시한다. **추정치로 채워 실측치처럼 보이게 하지 않는다**

## 2. 축(axis) 유형 카탈로그

| 유형 | 값의 성격 | 컨트롤 | 기본값 잡는 법 |
|---|---|---|---|
| 기간(date) | 연속·순서 있음 | 날짜 선택 / 기간 슬라이더 | 가장 최근 구간 |
| 범주(category) | 유한한 이름 목록 | select(단일) / 칩(다중) | 전체 또는 가장 비중 큰 것 |
| 위치(geo) | 계층 있는 범주 | 지도 클릭 / select | 전체(지도 확대 전 상태) |
| 비교대상(compare) | 같은 지표의 다른 기준 — 이전 구간(전기·전년) 또는 **비교군**(다른 대상의 평균) | 토글 | 전기·전년이면 더 흔히 쓰는 것, 비교군이면 가장 조건이 비슷한 것 |

- **범주 축은 선택지가 20개를 넘으면** select를 칩으로, 또는 검색 가능한 목록으로
  바꾼다. 20개를 넘는 드롭다운은 스크롤로 찾아야 해서 탐색이 아니라 탐색 실패가 된다
- **위치 축은 계층을 존중한다.** 시도 → 시군구처럼, 상위를 클릭해 하위로 내려가는
  구조로 만든다. 처음부터 시군구 250개를 한 목록에 펼치지 않는다
- **비교할 때는 비교군을 둔다.** 대상 하나의 숫자는 무엇과 견주느냐에 따라 뜻이 바뀐다.
  이전 구간(전기·전년)만이 아니라 같은 시점의 다른 대상 묶음 — 예: 전국 평균, 시도 평균,
  조건이 비슷한 세그먼트 평균 — 을 비교군으로 둔다. **비교군이 둘 이상이면 토글로 하나만
  고르게 하지 않고 한 화면에 함께 둔다** — 각각 다른 질문에 답한다. 토글은 차이를 어느
  비교군 기준으로 잴지처럼 값 하나만 필요한 자리에만 쓴다. 비교군을 어떻게 구성할지는
  질문과 데이터마다 정한다
- **평균으로 묶은 비교는 펼쳐 볼 수 있게 한다.** 비교군 평균 옆에서 모달을 열면 선택 대상과
  비교군 구성원 전체를 같은 지표로 내림차순 줄 세우기(순위·값·평균선, 선택 대상 강조)로
  보여준다. 모달 안에서 비교군과 지표를 바꿀 수 있게 한다 — 규모와 순위를 한 자리에서 본다
- 기본값 없이 "전체"로 열리는 축은 두지 않는다. 전체가 기본값이면 그렇게 명시한다 —
  암묵적으로 전체인 것과 명시적으로 전체를 고른 것은 화면에서 구분되어야 한다

## 3. 패널(panel) 유형 카탈로그

| 유형 | 보여주는 것 | 필요한 그레인 | 흔한 함정 |
|---|---|---|---|
| KPI | 현재 필터 조합의 합계·비교값 | 축 전체 | 비교값 없이 숫자만 두면 KPI가 아니다. 첫 줄은 금액·부수 같은 원래 단위로 |
| trend | 시간에 따른 값의 변화 | 기간 + 그 외 축 | 계열이 5개를 넘으면 못 읽는다 — 상위 N + 기타 |
| mix | 구성 비중. 분류에 위계가 있으면 계층 드릴다운(대분류 → 중분류 → 소분류), 없으면 상위 N + 기타 드릴다운 | 대상 축 | 위계가 있는데 한 목록에 펼치면 flat해진다. 기타를 클릭해도 안 열리면 그 기타는 숨긴 데이터다 |
| map | 지역별 분포 | 위치 축 | 막대로도 되는 것을 지도로 그리지 않는다(design-rules 참고) |
| table | 상세 행 단위 | 축 전체 | 정렬 가능한 표라고 12행 넘는 원자료를 그대로 두지 않는다 |
| tree_table | 위계가 있는 항목 전체를 접고 펴는 표(▸를 펴면 한 단계 아래) | 대상 축 | 처음부터 전부 펼쳐 두면 flat한 긴 표와 같다. 처음엔 대분류만 |

- **패널마다 반응하는 축을 명시한다.** 반응하지 않는 축이 있는 패널은 왜 있는지
  다시 확인한다 — 전역 필터가 아무 의미도 없는 패널일 수 있다
- **비교는 직관적인 단위에서 시작한다.** 첫 패널·첫 줄은 금액·부수 같은 원래 단위와,
  크기를 맞춘 값(인구 1천 명당 매출액, 점포 1곳당 부수 등)으로 비교한다. 증감률·지수·
  구성비는 그 아래에 둔다 — 비율부터 보여주면 "그래서 얼마나 큰가"가 안 보인다
- **위계가 있는 분류는 위계대로 내려간다.** 한 번에 한 단계만 펼치고, 지금 어느 단계에
  있는지 경로(breadcrumb)로 보인다. 각 단계의 비중은 바로 위 분류 안에서의 비중이다
- **기타(etc) 드릴다운은 상위 N을 정한 근거가 있어야 한다.** "일단 5개만" 식으로
  임의로 자르면, 6번째와 5번째의 차이가 크지 않은데 하나는 보이고 하나는 숨는다.
  분포를 보고 자연스러운 끊는 지점(누적 비중 80% 등)을 찾는다

## 4. 계산 엔진 원칙

`references/template/explore-engine.js`가 공용 계산 함수를 담는다. 패널마다
새로 함수를 짜지 않는다 — 아래를 공용으로 쓴다.

| 함수 성격 | 하는 일 |
|---|---|
| 필터링 | 현재 축 선택값으로 그레인 원자료를 좁힌다 |
| 합산(rollup) | 좁힌 원자료를 지표별로 합·평균 낸다 |
| 가중평균(wavg) | 비율 지표(공급률 등)를 단순 평균이 아니라 가중평균으로 합친다 |
| 재정규화(renorm) | 상위 N + 기타로 묶을 때 비중을 다시 100%로 맞춘다 |
| 비교(전기·전년) | 같은 필터를 이전 구간에 적용해 비교값을 만든다 |

**패널 하나에만 쓰는 계산이 필요해지면, 그건 엔진에 함수를 하나 더 추가할지를
먼저 검토한다.** 패널 파일 안에 계산 로직을 박아 넣으면 다음 패널에서 같은 계산이
필요할 때 또 새로 짜게 된다 — 업로드된 참고 사례(claude_v13-dashboard-workfile.html)가
이 문제를 보여준다. 함수 150개가 대부분 특정 패널에 딱 붙어 있어 재사용이 안 됐다.

## 5. 파일 크기 관리

탐색형은 그레인 전체를 싣기 때문에 보고형보다 파일이 커진다. 아래로 관리한다.

- **정밀도를 낮춘다.** 소수점 넷째 자리까지 실을 이유가 없으면 둘째 자리로 자른다
- **기간을 자른다.** 화면에서 볼 수 있는 최대 기간을 정하고, 그보다 오래된 데이터는
  별도 파일이나 서버 조회로 뺀다. "전체 이력"을 한 파일에 다 넣지 않는다
- **문자열 반복을 줄인다.** 범주 이름을 매 행마다 문자열로 두지 않고 코드로 매핑한다
- 그래도 크면 사용자에게 **범위를 좁히자고 먼저 제안**한다. 압축 트릭보다 범위
  합의가 먼저다 — 왜 이 기간·이 단위까지 필요한지 3장(frame-explore)에서 다시 확인한다

## 6. 화면 위계와 위치 — 섹션 목차

패널이 여러 주제로 갈리면(예: 실적·지역·구성·수익성) 필터만으로는 화면 안에서 길을
잃는다. 필터는 "무엇을 볼지"를 좁히고, 목차는 "어디를 보고 있는지"를 알려준다.

- 패널을 **섹션(대분류)**으로 묶고, 섹션 안 패널을 **중분류**로 둔다. 번호는 `1` / `1.1`
- 왼쪽에 **접을 수 있는 사이드바 목차**를 둔다. 접으면 섹션 번호만 남은 좁은 띠가 되고,
  지금 보는 섹션 번호가 강조된다. 조건 바에도 "현재 위치: 3 상품 구성 › 3.1"을 늘 보인다
- 좁은 화면(모바일)에서는 사이드바 대신 섹션 이름만 가로로 흐르는 띠로 바꾼다
- 섹션이 하나뿐이거나 패널이 4개 이하면 목차를 두지 않는다

## 7. 글을 줄이는 법

탐색형은 결론 문장이 없다. 대신 "읽는 법"과 "기준·비고"가 줄글로 쌓이기 쉽다.

- 패널 위 설명 문장은 **이름·숫자 쌍의 칩**으로 쓴다 (예: `학령인구 48,194명` `비교군 10곳`).
  문장으로 이어 쓰지 않는다
- **사용법**(행을 누르면 내려간다 등)과 **기준·비고**(산식, 제외 조건, 출처 세부)는 화면에서
  숨기고 패널 제목 옆 ⓘ 버튼 뒤에 둔다 — 마우스를 올리면 짧은 툴팁, 누르면 모달.
  모달 안에서는 "사용법"과 "기준·비고"를 나눠 보인다
- 숨긴다고 지우지 않는다. 각주 4요소(출처·기간·단위·집계기준)는 보이는 한 줄로 줄여 남기고,
  세부만 ⓘ 뒤에 둔다
